# agv/ — JETANK 탐색 주행

로봇이 바닥 라인을 따라 돌면서 색 패치와 갈림길(갈라짐·합쳐짐)을 검출해 이벤트 로그로 남기고, 안 가 본 가지를 골라 매트 전체를 탐색한다. 맵은 그 로그로 `mapping/build_map.py`가 만든다.

Jetson Nano 기본 이미지(Python 3.6, OpenCV, jetbot)에서 돌아가며, 추가 설치는 필요 없다.

## 구성

| 파일 | 내용 |
| --- | --- |
| `explore.py` | 실행 진입점. 카메라 → 인식 → 이벤트 기록 → 모터 |
| `runner.py` | 한 프레임 처리 로직. 시뮬레이터(`sim/mat/`)도 같은 코드를 쓴다 |
| `linecam.py` | 라인·색 패치·갈림길 검출, 라인 추종 조향 |
| `topo/` | 이벤트 로그 형식, 탐색 정책(안 가 본 가지 우선), 맵 빌더, 주행 기록으로 맵 모양 계산(`shape.py`) |
| `hw.py` | 카메라(GStreamer / jetbot / 녹화 영상), 모터(jetbot Robot) |
| `arm.py` | 카메라 자세(팔 서보 1·2·3·5번 각도) 읽기·맞추기·저장. 저장한 자세는 시작할 때 자동으로 맞춤 |
| `tools/camtool.py` | 현장 보정: 카메라 자세 맞추기·저장(`arm`), 화면 저장(체커보드 확인 포함), 바닥 좌표계용 회전 사진, HSV 측정, 속도 측정 |
| `camcalib.py`, `tools/calib.py` | 체커보드 사진으로 렌즈 보정값(어안/핀홀 자동 선택) 계산·불러오기 |
| `speedcal.py` | 색 패치를 지날 때마다 실제 주행 속도를 다시 재서 이동거리 보정 |
| `tools/autocolor.py` | 한 바퀴 영상에서 패치 색 범위·문턱 자동 보정 |
| `tools/runlog.py` | 주행 결과(events.jsonl) 요약: 타임라인, 막다른 길·V자 값, 종료 이유 |
| `config/explore.json` | 현장 값(속도, HSV, 카메라). `linecam.DEFAULT_CONFIG`를 덮어쓴다 |

## 현장 순서

막다른 길·V자까지 단계별로 시험하는 체크리스트는 [FIELD_TEST.md](FIELD_TEST.md)에 있다. 주행 결과 요약은 `python3 -m agv.tools.runlog data/runs/<시각>`으로 본다.

저장소 루트에서 실행한다. 주피터 노트북이 카메라를 잡고 있으면 먼저 그 커널을 끈다.

1. **카메라 자세 정하기(처음 한 번)**: `python3 -m agv.tools.camtool arm --view`
   - 로봇을 라인 위에 놓고 브라우저(`http://<젯슨 IP>:8080`)로 검출 화면을 보며 키보드로 맞춘다. `1`·`2`·`3`·`5`로 서보(팔 좌우, 팔 아래 관절, 팔 가운데 관절, 카메라 상하)를 고르고 `+`/`-`로 움직인다(`[` 1도씩, `]` 5도씩). 손으로 맞추려면 `f`로 힘을 뺐다가 `f`로 고정한다. `p`로 저장, `q`로 끝.
   - 라인이 화면 아래 절반의 가운데쯤 보이고, 가로줄마다 초록 점이 하나씩 찍히면 된다. 상태 표에 "선 하나로 보이는 줄", "조향 줄 선 위치"가 숫자로 나온다. `--view`가 없으면 `data/snap/arm_preview.png`를 계속 저장한다.
   - 저장한 각도(`config/explore.json`의 `arm.servo_angles`)는 이후 `explore`, `camtool snap`/`ground`, `autocolor --camera`가 시작할 때 자동으로 맞춘다. 맞춘 뒤 다시 읽어 3도 넘게 다르면 경고한다. 팔을 건드리지 않으려면 `--no-arm`. `camtool arm --read`는 지금·저장한 각도 출력, `--apply`는 맞추기만, `--save-now`는 지금 자세를 그대로 저장.
   - 자세를 다시 저장하면 그 자세에서 잰 값(5번 판정 지점 거리, 7번 렌즈 보정·바닥 사진)을 다시 잰다. 저장할 때 목록이 나온다.
   - 확인: `python3 -m agv.tools.camtool snap` → `data/snap/debug.png`. `full.png`(원본 해상도)도 같이 저장된다. 검출 그림과 HSV 측정은 주행 해상도인 `raw.png` 기준이다.
   - GStreamer가 안 열리면 `--camera jetbot`으로 바꾼다(이때는 노출 고정이 안 됨). JetPack이 오래돼 `aelock`을 모르면 `camera.lock_exposure`를 `false`로 둔다.
2. **색 자동으로 잡기**: 맵을 한 바퀴 도는 영상에서 패치 색 범위를 자동으로 잡는다. 라인 추종은 검은 선만 보므로 색이 안 맞아도 로봇이 직접 돌 수 있다.
   - `python3 -m agv.explore --mode ask --enable-motors --record --view`로 한 바퀴 돈다. 갈림길에서는 바깥쪽 큰 고리를 골라 모든 패치를 한 번씩 지나게 한다(고를 쪽은 `FIELD_TEST.md` 2단계). 이 주행의 패치 검출은 틀려도 상관없고 영상만 있으면 된다. 주황으로 돌아오면 Ctrl+C로 멈춘다.
   - 모터가 준비되지 않았거나 선을 못 따라가면 대신 `--mode passive`로 로봇을 손으로 밀어 한 바퀴 녹화한다.
   - 처음 바퀴를 굴리기 전에 앞으로 가는지 확인한다. 바퀴 방향이 반대면 `robot.invert_left/right`를 고친다.
   - `python3 -m agv.tools.autocolor data/runs/<시각>` → 색마다 새 H 범위, 바꿀 문턱, **그 영상에서 잡히는 패치 순서(기존 설정 vs 새 설정)**가 나온다. `autocolor.png`에서 이름표와 실제 패치 사진이 맞는지 본다.
   - 괜찮으면 `--write`를 붙여 다시 실행한다. `config/explore.json`에 쓰고 원래 파일은 `.bak-<시각>`으로 남는다. 라인 문턱(`line.v_max` 등)은 지금 값이 안전한 범위면 그대로 둔다.
   - 조명이 바뀌면(낮/밤, 다른 강의실) 한 바퀴 다시 찍어 돌리면 된다. 녹화 없이 `--camera gst --seconds 60`으로 카메라에서 바로 찍을 수도 있다.
   - 이름은 무지개 순서(빨강→주황→노랑→초록→파랑→보라)로 붙인다. 매트에 일부 색만 있으면 `--colors red,blue,...`로 알려 준다. 바닥·신발 같은 다른 색이 잡히면 화면에 안 들어오게 다시 찍는다.
   - 손으로 재야 할 때: `snap` 후 `python3 -m agv.tools.camtool hsv data/snap/raw.png x y w h`.
3. **검출 확인**: 보정한 색으로 한 바퀴 더 돈다(`--mode ask --enable-motors --record`, 모터 없이 보려면 `--mode passive`로 손으로 밀기).
   - 터미널에 `patch`(맵의 색 전부), `split`, `merge` 이벤트가 찍혀야 한다.
   - 결과 폴더의 `debug/*.jpg`에서 검출 상태를, `camera.mp4`로는 노트북에서 다시 돌려 볼 수 있다: `python3 -m agv.explore --camera video:<폴더>/camera.mp4`
4. **패치 길이 재기**: 색 패치의 진행 방향 길이를 자로 한 번 재서 `patch.length_mm`에 넣는다(패치는 모두 같은 크기). 그러면 주행 중 패치를 지날 때마다 실제 속도를 다시 재서 이동거리를 보정한다. 배터리가 닳아 느려지거나 바닥이 바뀌어도 따라간다. `robot.speed_mm_s`는 첫 패치를 지나기 전까지만 쓰는 짐작값이라 기본값(150)으로 둬도 된다. 바퀴 방향이 반대면 `robot.invert_left/right`를 고친다.
   - 패치 길이를 못 쓰는 맵이면 예전처럼 `python3 -m agv.tools.camtool speed --enable-motors`로 속도를 재서 `robot.speed_mm_s`에 넣는다.
5. **판정 지점 거리 재기**: `snap`의 `debug.png`에서 파란 가로줄이 바닥 어디에 해당하는지 자로 재서 `geom.ctrl_ahead_mm`에 넣는다(차체 궤도 가운데 기준).
6. **갈림길만 사람이 고르는 주행**: `python3 -m agv.explore --mode ask --enable-motors`
   - 갈라지는 곳에서 멈추고 왼쪽/오른쪽을 묻는다. 라인 추종이 흔들리면 `follow.base_speed`를 낮추고 `follow.kp`를 조정한다.
7. **렌즈 보정(카메라 캘리브레이션)**: 지금 주행과 맵 생성에는 안 쓴다. 다음 단계(카메라와 패치로 바닥 mm 좌표를 재서 맵 모양을 더 정확하게)에 필요하니 현장에 간 김에 찍어 둔다. 계산은 노트북에서 해도 된다.
   - 주행 자세(팔 각도) 그대로 `python3 -m agv.tools.camtool snap --count 25 --out data/calib`. 1.5초마다 한 장씩 찍으며 장마다 체커보드가 보였는지(O/x) 알려 준다. 보드를 화면 가운데·네 귀퉁이·가장자리로, 30~45도 기울여 가며 옮긴다.
   - `python3 -m agv.tools.calib data/calib` → 일반(핀홀)·어안 모델을 둘 다 계산해 재투영 오차가 작은 쪽을 고른다. 오차 1px 아래, 화면 덮은 비율 60% 이상이면 좋다. `calib_check.png` 오른쪽(편 사진)에서 곧은 선이 곧게 보이는지 확인하고 `--write`로 `config/camera_calib.json`에 저장한다.
   - 보정값은 그 센서 모드에서만 맞는다. `camera.capture_width/height`나 `flip`을 바꾸거나 초점 링을 돌리면 다시 찍는다(주행 시작 때 안 맞으면 경고).
   - 설계 문서 5.2절은 ChArUco 보드를 쓰지만, Jetson 기본 OpenCV(4.1.1)에는 aruco 모듈이 없을 수 있어 일반 체커보드를 쓴다. 렌즈 보정값은 같게 나온다. 보드 크기(안쪽 모서리 9x6 등)는 자동으로 찾고, 칸 크기는 결과에 영향이 없다.
   - 같이 찍어 둘 것: 로봇을 라인 위, 패치가 앞 15~25cm에 통째로 보이게 세우고 `python3 -m agv.tools.camtool ground --enable-motors --out data/ground` (제자리에서 좌우로 조금씩 돌며 9장).
8. **자율 탐색**: `python3 -m agv.explore --mode drive --enable-motors --record`
   - 갈림길마다 안 가 본 쪽을 고르고, 모든 가지를 다 돈 뒤 같은 패치로 한 바퀴 깨끗하게 돌아오면 그 패치에서 멈춘다(`end` 이벤트의 `reason`이 `explore_explored`).
9. **맵 만들기**: `python3 mapping/build_map.py data/runs/<시각>/events.jsonl -o maps/<이름>.json` → `mapping/viewer/index.html`에 끌어다 놓는다.
   - 같은 폴더의 `trace.jsonl`로 로봇이 실제로 지나간 궤적을 되살려 노드 좌표와 엣지 곡선을 계산한다(렌즈 보정 불필요). 터미널의 `모양 계산` 줄에서 같은 노드 방문 위치 차이가 작은지 본다. 자세한 내용과 트윈으로 보내는 `--twin`은 [mapping/README.md](../mapping/README.md).

**실시간 화면**: 어느 모드든 `--view`를 붙이면 로봇이 웹 서버를 띄운다. 터미널에 나온 주소(`http://<젯슨 IP>:8080`)를 같은 와이파이의 노트북·폰 브라우저로 연다. 검출 그림, 주행 상태(라인 추종/후진/회전), 최근 이벤트, **정지 버튼**이 나온다. 와이파이가 기기끼리 통신을 막으면 SSH로 포트를 넘겨 `ssh -L 8080:localhost:8080 <사용자>@<젯슨 IP>` 후 `http://localhost:8080`로 연다. 보는 사람이 없으면 그림을 만들지 않아 주행에 영향이 없다. 모니터가 연결돼 있으면 `--show`로 OpenCV 창을 띄울 수도 있지만, `ssh -X`로 원격 창을 띄우면 느려서 `--view`를 권한다. 녹화 영상 재생(`--camera video:...`)에 `--view`를 붙이면 실제 속도로 재생된다.

Ctrl+C를 누르면 모터를 세우고 `end` 이벤트를 남긴 뒤 끝난다. ask·drive 모드는 `--enable-motors` 없이는 실행되지 않는다.

## 검출 방식과 조정 값

카메라는 앞 바닥을 비스듬히 본다(화면 아래 = 가까움). 스캔 영역에 가로줄 14개를 긋고 줄마다 라인 조각을 찾는다.

- **라인**: 어둡고(`v_max`) 채도 낮은(`s_max`) 픽셀. 아주 어두운 픽셀(`v_dark`)은 채도와 상관없이 라인으로 본다. 어두운 곳은 노이즈로 채도가 튀어서, 이 처리가 없으면 선이 두 조각으로 쪼개진다.
- **색 패치**: 화면 아래쪽(`patch.region_top`부터)에서 그 색 비율이 `on_frac`을 넘으면 진입 이벤트를 낸다.
- **갈림길**: 조향 줄(`line.control_row`, 차체 바로 앞)에서 조각 수가 바뀌는 순간을 본다.
  - 1개에서 2개로 바뀔 때 두 조각이 붙어 있고 간격이 벌어지면 **갈라짐**이다. 이때 탐색 정책이 갈 쪽을 고른다.
  - 2개에서 1개로 바뀔 때 두 조각이 붙어 있었으면 **합쳐짐**이다.
  - 옆에서 다른 선이 들어오거나 나가는 경우(간격이 좁아지거나 처음부터 멂)는 무시한다.
  - 갈라짐 이벤트의 `onset`(간격/라인폭 비율, 간격 변화 px)을 보고 `junction.split_*` 값을 조정한다. 시뮬레이션에서 갈라짐은 비율 1.2~1.7·변화 +15 이상, 옆 선 진입은 비율 1.8 이상·변화 음수였다.
- 앞쪽에 갈래 모양이 보이는 것(`fork_ahead`)만으로는 방향을 정하지 않는다. 합류 지점에 옆 가지로 들어갈 때도 화면상 똑같이 보여서, 그걸 믿으면 반대 가지로 역주행한다(시뮬레이터에서 실제로 겪음).
- **X자 교차**: 합류가 나면 바로 기록하지 않고 `junction.cross_window_mm`(300mm) 동안 보류한다. 그 안에 선이 다시 갈라지는데 다른 선이 내가 있던 쪽으로 빠져나가면 교차다. 판단은 두 가지로 한다. 하나는 그쪽 조각이 더 비스듬한지, 다른 하나는 그 조각 기울기가 합류 직전 다른 선 기울기와 이어지는지다. 교차면 `cross` 이벤트를 남기고 곧은 선을 따라간다. 아니면 보류한 합류를 기록하고 보통 갈림길로 처리한다. 보라 패치 뒤 렌즈처럼 합류 직후 같은 쪽으로 다시 갈라지는 경우가 여기에 해당한다.
- **급한 가지(V자)**: 모서리 곡선 위에서 급하게 꺾여 나가는 가지는 갈라지는 모습이 안 보이고, 옆에서 들어와 내 선에 붙는 선(합류 모양)으로 보인다. 옆 선이 가파르게 들어와 `junction.vee_max_frames`(5) 안에 붙고, 붙은 뒤 내 선이 그 선 쪽으로 `vee_cont_px`(줄당 4px) 이상 휘어 나가면 그쪽에 급한 가지가 있다고 본다. 반대쪽으로 휘면 옆에서 붙는 T자 합류다(빨강 앞 합류처럼). 탐색 정책이 그 가지를 고르면 차체 중심이 만나는 점에 올 때까지 간 뒤 그쪽으로 제자리 회전해 가지를 탄다(`note` `vee_pivot`·`vee_done`). 시뮬레이션에서 S자 선 갈림길은 휨 9~13, 빨강 앞 T자 합류는 반대 방향 22 정도였다.
- **속도 보정(패치)**: 화면의 한 가로줄은 바닥의 한 선이다. 패치 앞 가장자리가 그 선을 지나는 순간부터 뒤 가장자리가 지날 때까지 로봇은 정확히 패치 길이만큼 움직이므로, 그사이 적분한 모터 명령으로 패치 길이를 나누면 실제 속도가 나온다. 렌즈 왜곡이나 카메라 각도와 상관없다. 가로줄 10개에서 따로 재 중앙값을 쓰고, 지나는 동안 크게 돌았거나(곡선, `speedcal.turn_max`) 줄마다 값이 흩어지면(`max_spread`) 버린다. 첫 측정은 그대로, 그 뒤로는 40%씩 섞는다. 시뮬레이션에서 실제 속도가 설정보다 20% 느리고 1분에 5%씩 더 느려질 때, 패치 사이 거리 오차가 보정 없이는 +30%, 보정하면 중앙값 2% 안팎이었다. 곡선에서 궤도가 미끄러져 덜 도는 것은 주행 중에는 보정하지 않고, 맵을 만들 때 같은 노드로 돌아온 고리로 맞춘다(`trace.jsonl`, [모양 계산](../mapping/README.md#모양-계산-주행-기록)).
- **스퍼(T자)**: 조향 줄의 선 조각이 한쪽으로만 라인폭의 3배 넘게 넓어지고, 조향 줄에서 3줄 위·아래는 보통 폭 선 하나뿐일 때 `tee`로 기록한다. 띠가 얇은지 보는 이 조건으로 곡선 합류를 스퍼로 잘못 보는 것을 거른다. 라인 추종은 넓은 조각에서 내 선 쪽 가장자리를 쓰므로 스퍼 쪽으로 끌려가지 않는다.
- **이벤트 위치**: `geom.ctrl_ahead_mm`·`geom.patch_ahead_mm`만큼 앞당겨, 차체 위치가 아니라 판정한 바닥 지점으로 기록한다. 확정이 몇 프레임 늦어도 처음 감지한 프레임 기준이다.

## 막다른 길에서 되돌아 나오기

갈림길이나 교차에서 고른 쪽으로 60cm 안에 선이 끝나면 막다른 길(스퍼)로 보고 되돌아 나온다. drive·ask 모드에서만 동작한다.

1. **감지**: 조향 줄부터 위쪽 줄에 선이 하나도 없고 아래쪽 줄에만 있는 상태가 3프레임 이어지면 선 끝으로 본다. 선을 완전히 놓친 지 0.3초가 지나도 같다. 멈추고 `dead_end`를 기록한다. 스퍼 길이는 갈림길에서 선 끝까지다.
2. **후진**: 화면 속 선 기울기로 방향을 잡으며, 차체 중심이 갈림길 지점에 올 때까지 후진한다. 거리는 모터 명령으로 잰다.
3. **회전**: 스퍼 반대쪽으로 제자리 회전한다. 스퍼 선이 화면 가운데를 벗어난 뒤 다른 선이 가운데에 오면 멈추고 다시 따라간다.
4. **기억**: 탐색 정책은 그 갈림길을 막다른 길로 기억한다. 다음에 만나면 묻지 않고 반대쪽으로 가고 `tee`로 기록한다. 맵에는 스퍼 길이가 남는다.

곡선에서 합류한 직후의 스퍼처럼 비스듬히 만나는 스퍼를 갈림길로 착각해도, 이렇게 맵을 고치지 않고 탐색을 이어 간다. 나중에 스테이션에서 스퍼로 빠졌다 나오는 동작에도 같은 후진·회전을 쓸 수 있다.

현장에서 확인할 것:

- **선 끝 너머 바닥**: 매트 밖 카펫이 어두우면 선으로 잡혀 끝을 못 알아본다. 스퍼 끝에서 `snap`을 찍어 `line_mask.png`에 카펫이 하얗게(선으로) 나오지 않는지 본다. 나오면 `line.v_max`를 낮추거나 스퍼 끝에 흰 종이를 댄다.
- **후진 거리**: 궤도가 후진할 때 전진과 속도가 다르면 갈림길보다 덜 또는 더 물러난다. 회전 뒤 선을 못 찾으면 `recover.back_extra_mm`를 조정한다.

## 맵(테이프) 배치 규칙

시뮬레이터에서 탐색이 막혔던 경우를 바탕으로 정했다. 카메라는 차체 앞 약 12cm를 보고 따라가므로, 곡선을 도는 중에는 차체가 선보다 늦게 돈다.

- **스퍼**는 직선 구간에 직각으로 붙이고, 모서리·합류·분기·교차에서 15cm 이상 띄우는 게 가장 좋다. 곡선에서 합류한 직후의 스퍼는 아직 꺾는 중인 로봇에게 비스듬한 가지로 보인다. 이 경우 탐색은 막다른 길 되돌아 나오기로 이어 가지만, 매번 한 번씩 들어갔다 나오느라 시간이 든다.
- **갈림길**은 진행 방향에서 30도 이내로 완만하게 갈라지게 하는 게 가장 안전하다. 모서리 곡선 위에서 급하게 꺾여 나가는 가지(도안의 S자 선 시작점)는 V자 처리로 들어가지만, 제자리 회전에 기대므로 실물에서 먼저 확인한다. 회전 뒤 원래 곡선을 다시 타면 `recover.pivot_center`나 회전 속도를 조정한다.
- **교차**는 30도 이상 각도로 지나가게 하고, 교차 위에 스퍼를 두지 않는다.

## 이벤트 로그

`data/runs/<시각>/events.jsonl`에 한 줄에 하나씩 기록된다. 형식은 `topo/events.py` 맨 위에 있다.

```json
{"ts": 1730700000.85, "seq": 1, "type": "patch", "odo_mm": 127.0, "color": "orange"}
{"ts": 1730700012.95, "seq": 3, "type": "split", "odo_mm": 1735.2, "choice": "left", "cmd": "left", "onset": {"ratio": 1.23, "trend": 16.0}}
{"ts": 1730700014.10, "seq": 5, "type": "merge", "odo_mm": 2013.4, "from_side": "left"}
```

같은 폴더의 `trace.jsonl`에는 프레임마다 이동거리(`o`)와 좌우 모터 명령 차이 적분(`y`, 그중 제자리 회전 몫 `p`)이 남는다. 맵 빌더가 이것으로 실효 궤도 폭을 맞추고 맵 모양(노드 좌표·엣지 곡선)을 계산한다([mapping/README.md](../mapping/README.md#모양-계산-주행-기록)). passive 모드에서는 모터 명령이 없어서 남기지 않는다.

`odo_mm`은 모터 명령 × 속도를 적분한 추정 이동거리에 판정 지점까지 거리(`geom`)를 더한 값이다. 속도는 `patch.length_mm`가 있으면 패치를 지날 때마다 다시 잰 값(`note` `speed_cal`)을 쓴다. passive 모드에서는 `null`이고, 이때 빌더가 시간 × 속도로 대신 계산한다. 교차는 `cross`(다른 선이 들어온 쪽 `from_side`), 스퍼는 `tee`(`side`)로 남는다.
