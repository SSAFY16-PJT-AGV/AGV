# 실기체 현장 시험 매뉴얼 (2m × 1m 맵)

이 순서대로 하면 기본 보정부터 막다른 길 되돌아 나오기, 급한 가지(V자) 들어가기, 자율 탐색, 완성된 맵에서 목표 패치로 가기(9단계)까지 하나씩 확인할 수 있다. 각 단계는 **명령 → 통과 기준 → 안 되면 고칠 값** 순서다. 앞 단계를 통과해야 다음 단계 결과를 믿을 수 있다.

보정 명령의 자세한 설명은 [README.md](README.md)의 "현장 순서"에 있다. 이 문서는 시험 순서와 판정 기준을 다룬다.

**맵 파일만 빨리 뽑을 때**: 0 → 1(카메라 자세·패치 길이·판정 지점 거리) → 2(첫 바퀴 + 색 보정) → 3(확인 바퀴) → 6(자율 탐색 + `build_map`). 4·5단계(막다른 길, V자)는 6단계 자율 탐색이 그 자리에서 막힐 때 돌아와서 한다. 카메라 자세와 색은 한 번 저장하면 다음 날에도 그대로 쓰므로, 두 번째부터는 0 → 3 → 6만 하면 된다(조명이 크게 바뀌었으면 2도).

## 0. 준비

**가져갈 것**: 줄자, 마스킹테이프(시작 위치 표시), 노트북(영상 재생·맵 뷰어), 충전된 배터리

**Jetson에서 코드 받기** (저장소 루트):

```
git remote set-url origin https://github.com/SSAFY16-PJT-AGV/AGV.git   # 저장소 주소가 바뀜(한 번만)
git fetch origin
git checkout feature/topo-mapping
git pull
python3 -m unittest discover -s agv/tests      # sim/mat/이 없으면 시뮬레이션 테스트는 건너뜀
```

현장에서 저장한 설정(`autocolor --write`, `camtool arm`의 `p`, `calib --write`)은 `agv/config/` 안의 파일을 바꾼다. 그 상태에서 `git pull`이 "local changes would be overwritten"으로 멈추면 설정을 잠깐 치워 두고 받은 뒤 되돌린다.

```
git stash          # 현장에서 바꾼 설정 잠깐 치우기
git pull
git stash pop      # 되돌리기. 충돌이 나면 agv/config/explore.json에서 <<<< 표시 부분을 골라 고친다
```

**팔 서보 라이브러리 (처음 한 번)**: 카메라 자세(`camtool arm`)는 Waveshare 서보 라이브러리 `SCSCtrl`을 쓴다. `서보를 못 써요: SCSCtrl ... 못 찾았어요`가 나오면 설치한다.

```
cd ~ && git clone https://github.com/waveshare/JETANK.git
cd ~/JETANK && pip3 install --user .      # pyserial도 같이 설치됨. 설치 없이 ~/JETANK에 받아만 둬도 찾아 씀
python3 -m agv.tools.camtool arm --read   # 확인: 1·2·3·5번 각도가 숫자로 나오면 됨
```

- `접근 권한이 없어요`: `sudo chmod 666 /dev/ttyTHS1`(재부팅하면 풀림). 계속 쓰려면 JETANK의 `config.sh`처럼 udev 규칙(`KERNEL=="ttyTHS1",MODE="0666"`)을 넣는다.
- 각도가 `?`로 나오거나 서보가 반응하지 않음: 시리얼 콘솔이 포트를 잡고 있을 수 있다. `sudo systemctl stop nvgetty && sudo systemctl disable nvgetty` 후 재부팅. 주피터에서 서보 노트북을 열어 두었으면 그 커널을 끈다.
- JETANK의 `config.sh`를 통째로 돌리지는 않는다. 카메라 색 보정 파일(`camera_overrides.isp`)을 바꾸고 재부팅까지 해서, 색 보정을 다시 해야 할 수 있다.

**안전**
- `ask`·`drive` 모드는 `--enable-motors`를 붙여야만 바퀴가 돈다.
- **Ctrl+C**를 누르면 모터를 세우고 기록을 닫는다. 첫 주행은 손을 로봇 옆에 두고 한다.
- 주피터 노트북 커널이 카메라를 잡고 있으면 먼저 끈다.

**실시간 화면**: 아래 모든 `agv.explore` 명령에 `--view`를 붙이면, 터미널에 나온 `http://<젯슨 IP>:8080`을 노트북·폰 브라우저로 열어 검출 화면·주행 상태·이벤트를 실시간으로 볼 수 있다. 화면의 **정지** 버튼은 Ctrl+C와 같다. 접속이 안 되면 `ssh -L 8080:localhost:8080 <사용자>@<젯슨 IP>`로 접속한 뒤 `http://localhost:8080`을 연다. ask 모드의 갈림길 질문은 여전히 SSH 터미널에서 답한다(웹 화면에도 "질문 대기"가 뜬다).

**방향 약속**: 이 문서에서 위·아래·왼쪽·오른쪽은 **도안을 본 방향**이다. 로봇은 도안에서 시계 방향으로 돈다.

큰 바퀴 순서(시계 방향):

- **위 선**: 주황 → S_a(왼쪽 고리 오른쪽 변이 아래로 갈라짐) → 합류(M_b, S자 선이 올라와 붙음) → 보라 → 렌즈(짧게 갈라졌다 합쳐짐) → 초록
- **오른쪽 변**: 아래로 내려와 **오른쪽 아래 모서리**(S자 선이 급하게 갈라짐 = V자)
- **아래 선**: 노랑(S자 선과 교차) → 교차 한 번 더 → 합류(M_c, 왼쪽 고리 오른쪽 변이 붙음) → 빨강 → 빨강 스퍼 → 파랑 → 왼쪽 변을 올라가 주황

정확한 기대 맵은 뷰어(`mapping/viewer/index.html`)의 예시 맵(시뮬레이션 결과)을 본다.

로봇 진행 방향으로 보면 스퍼는 모두 바깥쪽(**왼쪽**)이고, S자 가지는 **오른쪽**이다. 반대 방향(반시계)으로 달리면 스퍼는 오른쪽에 보인다(9-6단계).

## 1. 기본 보정

| 순서 | 명령 | 통과 기준 |
| --- | --- | --- |
| 카메라 자세 (처음 한 번) | 로봇을 라인 위에 놓고 `python3 -m agv.tools.camtool arm --view` → 브라우저 화면을 보며 키보드로 팔·카메라 각도를 맞춤 → `p`로 저장 → `q` | 화면 아래 절반 가운데에 라인이 보이고 가로줄마다 초록 점이 하나씩 찍힘(상태 표의 "선 하나로 보이는 줄"이 거의 전부). 저장하면 `arm.servo_angles`에 들어가고, 이후 탐색·사진 찍기는 시작할 때 자동으로 이 자세로 맞춘다 |
| 자세 확인 | `python3 -m agv.tools.camtool snap` | 시작할 때 `카메라 자세를 저장한 값으로 맞췄어요`가 나오고, `data/snap/debug.png`가 위와 같음 |
| 패치 길이 | 패치의 진행 방향 길이를 자로 잼 | 그 값을 `patch.length_mm`에 적음. 주행 중 패치마다 속도를 자동으로 다시 잰다(속도 측정 불필요) |
| 판정 지점 거리 | `snap`의 파란 가로줄이 바닥 어디인지 줄자로 잼 | 그 값을 `geom.ctrl_ahead_mm`에 적음(궤도 가운데 기준) |
| 렌즈 보정 (다음 단계용) | `python3 -m agv.tools.camtool snap --count 25 --out data/calib`(보드를 화면 곳곳으로, 기울여 가며) → `python3 -m agv.tools.calib data/calib` → 확인 후 `--write` | 장마다 `보드 O`가 15장 이상, 재투영 오차 1px 아래, 화면 덮은 비율 60% 이상, `calib_check.png`에서 곧은 선이 곧게 펴짐. 지금 주행에는 안 씀 |
| 바닥 좌표계 사진 (다음 단계용) | 패치가 앞 15~25cm에 통째로 보이게 라인 위에 세우고 `python3 -m agv.tools.camtool ground --enable-motors --out data/ground` | `raw_*.png` 9장 모두에서 패치 네 모서리가 화면 안에 보임 |

패치 색은 2단계의 첫 한 바퀴 영상으로 잡는다.

카메라 자세는 한 번 저장하면 다음 날·다음 현장에서도 그대로 쓴다. 판정 지점 거리, 렌즈 보정, 바닥 사진은 그 자세에서 잰 값이라서 **자세를 다시 저장했으면 이 셋을 다시 잰다**(`camtool arm`이 저장할 때 목록을 보여 준다). 렌즈 보정은 찍을 때 자세를 같이 기록해서, 나중에 자세가 바뀌면 주행 시작 때 경고한다.

- 팔을 손으로 맞추는 게 편하면 `camtool arm`에서 `f`(힘 빼기) → 손으로 맞춤 → `f`(그 자리 고정) → `p`. 힘을 빼면 팔이 처지니 받친다.
- 주피터 등 다른 방법으로 맞춰 두었으면 `python3 -m agv.tools.camtool arm --save-now`로 지금 자세를 그대로 저장한다.
- 팔이 걸려 저장한 자세로 못 가면 시작할 때 `[주의] 카메라 자세가 저장한 값과 ...도 달라요`가 나온다. 팔 주변을 확인한다.
- 팔을 건드리지 않고 실행하려면 `--no-arm`.

> 속도(`patch.length_mm`로 자동 보정)와 `geom.ctrl_ahead_mm`은 막다른 길에서 후진하는 거리와 V자에서 회전을 시작하는 지점을 정한다. `ctrl_ahead_mm`을 대충 넣으면 4·5단계가 어긋난다.

## 2. 첫 한 바퀴 — 선 따라 돌며 녹화하고 색 자동 보정

라인 추종은 검은 선만 보므로 패치 색 설정이 맞지 않아도 돈다. 그래서 첫 바퀴는 로봇이 직접 돌게 하고, 그 녹화 영상으로 색을 잡는다.

```
python3 -m agv.explore --mode ask --enable-motors --record --view
```

주황 패치 조금 앞에 시계 방향으로 놓는다. 갈림길에서 `[l]왼쪽 / [r]오른쪽`을 물으면 **바깥쪽 큰 고리**를 돌도록 고른다. 그래야 패치 여섯 개를 다 지난다.

| 갈림길 | 고를 쪽 |
| --- | --- |
| 주황 뒤 첫 갈림길(S_a) | `l` (위 선 그대로. `r`은 왼쪽 고리 오른쪽 변으로 내려가 보라·초록·노랑을 건너뜀) |
| 렌즈 | 아무 쪽이나 |
| 오른쪽 아래 모서리 ("급한 가지(V자)가 오른쪽에 있음") | `l` (모서리 그대로) |
| 빨강 근처 (스퍼를 갈림길로 물을 때) | 원래 길 쪽 |

주황으로 돌아오면 Ctrl+C나 웹 화면의 **정지**로 멈춘다. 색이 아직 안 맞아 이 주행의 패치 이벤트는 틀릴 수 있다. 맵을 만들지 말고 색 보정용으로만 쓴다. 그다음 색을 잡는다:

```
python3 -m agv.tools.autocolor data/runs/<시각>            # 결과 확인
python3 -m agv.tools.autocolor data/runs/<시각> --write    # 괜찮으면 config/explore.json에 저장
```

**통과 기준**
- [ ] 곡선과 교차에서 선을 놓치지 않고 한 바퀴를 돈다. `runlog`에 `gap reason=line_lost`가 없어야 한다.
- [ ] 노랑 위 교차를 지날 때 꺾이지 않고 직진한다.
- [ ] 오른쪽 아래 모서리에서 "급한 가지(V자)가 오른쪽에 있음"을 묻는다. 빨강 앞 합류(왼쪽 고리 오른쪽 변이 아래 선에 붙는 곳)에서는 V자를 묻지 않는다.
- [ ] `autocolor`에서 여섯 색이 다 잡히고, `autocolor.png` 이름표가 실제 패치와 맞고, "새 설정" 패치 순서가 실제로 지나간 순서와 같다.

**안 되면**
- **흔들리거나 선을 놓침**: `follow.base_speed`를 0.3에서 0.25로 낮추고 `follow.kp`를 조정한다.
- **보라 패치 위에서 크게 흔들림**: 어두운 보라가 선으로 잡히는 것이다. 그 자리에서 멈추고 아래 "손으로 밀기"로 색을 먼저 잡는다. `autocolor`가 이 문턱(`line.v_dark`)도 같이 맞춘다.
- **색이 틀림**: 바닥·신발 같은 다른 색이 화면에 들어왔는지 보고 다시 찍는다. 매트에 일부 색만 있으면 `--colors`로 알려 준다.

**대안: 손으로 밀기 (모터 없이)**

모터가 아직 준비되지 않았거나 선을 따라가지 못하면, 로봇을 손으로 밀어 한 바퀴 녹화해도 된다.

```
python3 -m agv.explore --mode passive --record --view
```

주황 앞에 두고 도안의 시계 방향으로 바깥쪽 큰 고리를 한 바퀴 민다. 한 바퀴를 7~10초쯤(초당 15cm 안팎)으로 실제 주행 속도와 비슷하게 민다. 그다음 위와 같이 `autocolor`를 돌린다. 손으로 밀 때도 V자 판정이 기록된다(`runlog`의 `vee_seen`). 다만 판정이 프레임 수 기준이라 너무 천천히 밀면 놓칠 수 있다.

## 3. 색 확인 + 속도 보정 — 한 바퀴 더

```
python3 -m agv.explore --mode ask --enable-motors --record --view
python3 -m agv.tools.runlog data/runs/<시각>
```

2단계와 같이 바깥쪽 큰 고리를 고르며 한 바퀴 돈다. 이번에는 보정한 색으로 패치를 제대로 잡는지, 패치로 속도가 보정되는지 본다.

**통과 기준**
- [ ] `본 색`에 여섯 색이 모두, 지나간 순서대로 나온다.
- [ ] 노랑 근처에 `cross`가 나온다. 노랑 패치 위에서 S자 선과 교차해 패치 속성으로 흡수될 수도 있다.
- [ ] 오른쪽 아래 모서리에서 `vee_seen side=right`가 **한 번** 나온다. `cont`는 4 이상이어야 하며, 시뮬레이션에서는 9~13이었다. 빨강 앞 합류에서는 안 나온다.
- [ ] "속도 보정(패치)" 칸에서 받아들인 측정이 한 바퀴에 3번 이상이고, 잰 값들이 서로 10% 안이다.

**안 되면**
- **속도 보정이 계속 `[버림: turn]`**: 패치 근처에서 흔들리는 것이니 2단계의 흔들림 조정을 먼저 한다.
- **속도 보정이 `[버림: spread]`**: 패치 색이 고르게 안 잡히는 것이니 2단계 색 보정을 다시 한다.
- **엣지 길이가 통째로 어긋남**: 줄자로 잰 패치 사이 거리와 맵 엣지 길이가 통째로 몇 % 어긋나면 `patch.length_mm`를 다시 잰다.
- **모서리에서 `vee_seen`이 없음**: 7절 "영상으로 값 맞추기"를 참고한다.

## 4. 막다른 길 되돌아 나오기 (빨강 스퍼)

**시작 위치**: 왼쪽 고리 오른쪽 변의 중간쯤에 놓고, 아래(빨강 쪽)를 보게 한다.

```
python3 -m agv.explore --mode ask --enable-motors --record --view
```

1. 빨강 근처에서 갈림길을 물으면 **`l`(스퍼 쪽)**을 고른다.
2. 로봇은 스퍼 끝에서 멈추고, 후진하고, 제자리에서 돌아 원래 선으로 돌아와 파랑으로 간다.

스퍼를 갈림길이 아니라 `tee`로 보고 그냥 지나가면 묻지 않는다. 이것도 정상이다. 이 단계는 갈림길로 물어볼 때만 시험할 수 있다.

**통과 기준** (`runlog`의 "막다른 길" 칸, 3~5번 반복)
- [ ] `dead_end side=left spur_mm=…`가 나오고, 줄자로 잰 스퍼 길이와 ±5cm 안이다.
- [ ] `되돌아 나오기 완료 1 / 시작 1`이다.
- [ ] 그 뒤 `patch color=blue`가 나온다(원래 선으로 복귀).

**안 되면**

| 증상 | 고칠 값 (`config/explore.json`의 `recover`) |
| --- | --- |
| 스퍼 끝을 못 알아보고 매트 밖으로 나감 | `end_frames` 3 → 2. 스퍼가 600mm보다 길면 `window_mm`를 늘림 |
| 후진이 비뚤어짐 | `k_slope` 0.04 → 0.03(흔들림) 또는 0.05(덜 따라감). `reverse_speed`를 낮춤 |
| 갈림길보다 덜 물러나서 회전 뒤 스퍼로 다시 들어감 | `back_extra_mm` 10 → 30. 후진이 전진보다 느린 로봇일수록 늘린다 |
| 회전이 너무 지나치거나 덜 돎 | `pivot_speed` 0.22 → 0.18, `pivot_center` 0.15 → 0.10 |

## 5. 급한 가지(V자) 들어가기 (S자 선 시작점)

**시작 위치**: 오른쪽 고리 오른쪽 변에서, 오른쪽 아래 모서리보다 40cm쯤 위에 놓고 아래를 보게 한다. 테이프로 표시해 두고 매번 같은 자리에서 시작한다.

```
python3 -m agv.explore --mode ask --enable-motors --record --view
```

모서리에 다가가면 `갈림길이에요(급한 가지(V자)가 오른쪽에 있음)`이라고 묻는다.

**5-1. `r`(가지로 들어가기)** — 3~5번 반복
- [ ] 묻는 위치에서 10cm 남짓 더 가서 선이 만나는 점 위에 서고, 오른쪽으로 제자리 회전한다.
- [ ] 회전 뒤 **S자 선**을 탄다. 노랑 패치를 비스듬히 지나 교차하는 쪽이다. 원래 모서리 곡선(아래 선)을 다시 타면 실패다.
- [ ] `runlog` "V자" 칸에서 `들어가기 완료 1 / 회전 시작 1`이다.

**5-2. `l`(원래 길 계속)** — 2~3번 반복
- [ ] 멈칫하지 않고 모서리를 돌아 아래 선을 따라 노랑으로 간다.

**안 되면**

| 증상 | 원인·고칠 값 |
| --- | --- |
| 아예 묻지 않음 | `vee_seen`이 없으면 7절 방법으로 `junction.vee_max_frames`(5)·`vee_cont_px`(4)를 맞춘다 |
| 만나는 점보다 일찍 또는 늦게 회전 | `geom.ctrl_ahead_mm` 측정을 다시 한다. 속도 보정이 아직 한 번도 안 됐으면(`runlog`) 패치를 하나 지난 뒤 시험한다 |
| 회전 뒤 원래 곡선을 탐 | `recover.pivot_speed`를 낮추고 `pivot_center`를 0.10으로 줄인다 |
| 회전 뒤 S자 선을 지나쳐 계속 돎 | `pivot_center`를 0.20으로 늘린다 |
| 그래도 불안정 | 이 가지만 시작 각도를 20~30도로 완만하게 다시 붙이면 일반 갈림길로 처리된다(시뮬레이션 수정안 `ssafy_v2_fix`) |

## 6. 자율 탐색 + 맵 만들기

**시작 위치**: 주황 패치 조금 앞, 시계 방향을 보게 놓는다.

```
python3 -m agv.explore --mode drive --enable-motors --record --max-time 400 --view
python3 -m agv.tools.runlog data/runs/<시각>
python3 mapping/build_map.py data/runs/<시각>/events.jsonl -o maps/field_v2.json --map-id field_v2
```

`maps/field_v2.json`을 노트북의 `mapping/viewer/index.html`에 끌어다 놓는다. 언리얼 트윈에서 보려면 노트북에서 `--twin <트윈 프로젝트 폴더>`를 붙여 다시 실행하면 `Content/Data/warehouse_map.json`으로 복사된다(`mapping/README.md`의 "디지털 트윈(언리얼)에서 보기").

`build_map`은 Jetson에서 돌려도 되고, 폴더를 노트북으로 옮겨 돌려도 된다. 이때 `events.jsonl`과 `trace.jsonl`이 같은 폴더에 있어야 한다. 여러 번 돈 주행을 합치려면 `events.jsonl`을 여러 개 넣는다.

`build_map`은 같은 폴더의 `trace.jsonl`(프레임마다 남긴 이동거리·회전 기록)로 맵 모양을 계산한다. 터미널에 `좌표: 주행 궤적으로 계산`과 `모양 계산: 실효 궤도 폭 ...` 줄이 나와야 한다. 렌즈 보정 없이 패치 위치가 몇 cm 안으로 맞는 것이 목표다. 패치 가운데를 맞추려면 `patch.length_mm`가 설정에 들어 있어야 한다(3단계 속도 보정과 같은 값).

**통과 기준**
- [ ] `종료 이유: explore_explored`가 나온다. `max_laps`나 `line_lost`면 실패다.
- [ ] `build_map` 결과가 시뮬레이션 기대값과 같다: 패치 6, 갈라짐 3, 합쳐짐 3, 교차 2(같은 자리 한 쌍). 스퍼(T)는 0~1개다.
- [ ] `explore.complete`가 true다(미탐색 가지 없음).
- [ ] 큰 구간 길이(파랑→주황, 초록→모서리)를 줄자로 잰 값과 비교해 ±5% 안이다.
- [ ] 뷰어에서 맵이 매트와 비슷한 모양으로 그려진다(왼쪽 아래 `주행 궤적으로 계산한 좌표·곡선`). 매트 사진과 겹쳐 보거나, 패치 가운데끼리 거리 두세 개를 줄자로 재서 맵 좌표 거리와 비교한다(±5cm 안).
- [ ] `모양 계산` 줄의 `같은 노드 방문 위치 차이 평균`이 30mm 아래, 최대가 80mm 아래다. 실효 궤도 폭은 보통 실제 궤도 간격의 1.2~2배다.

모양이 이상할 때
- `[주의] 실효 궤도 폭이 잘 정해지지 않음`: 고리가 너무 적다. 같은 맵을 한두 바퀴 더 돈다(`--max-laps`를 늘림).
- 방문 위치 차이 최대가 크다: 그 노드의 판정이 틀렸을 가능성이 크다. `runlog`로 그 무렵 이벤트를 보고, 뷰어 이벤트 표에서 어느 관측이 그 노드로 묶였는지 확인한다.
- 전체가 조금 크거나 작다: 축척은 이동거리(패치 속도 보정)에서 온다. `speed_cal`이 몇 번 됐는지 `runlog`로 확인한다.
- `trace.jsonl이 없어서 엣지 길이로 추정한 배치를 씀`: `events.jsonl`만 옮겼거나, 손으로 민(passive) 주행이거나, 녹화 영상을 다시 돌린 결과다. 모터로 달린 원래 주행 폴더로 만든다.

`보라에서 나가는 길 2개` 경고는 보라 스퍼가 렌즈 분기에 가까워서 생긴다. 시뮬레이션에서도 가끔 나므로 이 경고 하나만 있으면 통과로 본다.

## 7. 영상으로 값 맞추기 (노트북)

`--record`로 찍은 `camera.mp4`를 노트북에서 다시 돌리면 로봇 없이 문턱값을 바꿔 볼 수 있다. 녹화 fps가 주행과 같아서 프레임 수 기준 판정도 그대로 재현된다.

```
cp agv/config/explore.json /tmp/try.json            # junction.vee_cont_px 등을 고쳐 본다
python3 -m agv.explore --camera video:data/runs/<시각>/camera.mp4 --config /tmp/try.json --out data/replay
# --view를 붙이면 브라우저(http://localhost:8080)에서 실제 속도로 보면서 재생
python3 -m agv.tools.runlog data/replay --all
```

- **모서리에서 `vee_seen`이 안 나옴**: `--all`로 그 시각 근처에 `merge`가 찍혔는지 본다. 찍혔다면 옆 선이 천천히 붙은 것이다. 이때는 `vee_max_frames`를 7로 올려 본다.
- **엉뚱한 곳에서 `vee_seen`**: 그 `cont` 값보다 `vee_cont_px`를 높인다. 단, 모서리의 `cont`보다는 낮게 유지한다.
- 고친 값은 `agv/config/explore.json`의 `junction` 아래에 적는다(`DEFAULT_CONFIG`를 덮어씀).
- 영상 재생은 모터를 쓰지 않아 `trace.jsonl`이 없으므로, 재생 결과로 만든 맵은 모양을 계산하지 않는다(엣지 길이로 추정한 배치). 맵 모양은 원래 주행 폴더로 만든다.

## 8. 결과 공유

시험한 주행마다 `data/runs/<시각>/` 폴더를 통째로 압축해 공유한다. 폴더에는 `events.jsonl`, `trace.jsonl`(맵 모양 계산용 회전 기록), `config_used.json`, `camera.mp4`, `debug/`가 있다. 어느 단계 시험인지와 통과 여부를 한 줄 적는다. 영상이 있으면 노트북에서 그대로 재현해 원인을 찾을 수 있다. 렌즈 보정·바닥 좌표계 사진(`data/calib/`, `data/ground/`)도 같이 공유하면 다음 단계(카메라로 바닥 mm 좌표를 재서 맵 모양을 더 정확하게)를 바로 이어서 만들 수 있다. 만든 맵 파일(`maps/*.json`)과 `agv/config/explore.json`(현장에서 저장한 카메라 자세·색)도 같이 올린다.

## 9. 완성된 맵에서 목표 패치로 가기 (goto)

코드는 아직 `feature/goto-nav` 브랜치에 있다(`feature/topo-mapping`에서 갈라짐). Jetson에서 `git fetch origin && git checkout feature/goto-nav && git pull`. 맵 파일(`maps/field_v2.json`)이 topo-mapping 쪽에만 있으면 `git checkout feature/topo-mapping -- maps/field_v2.json`으로 가져온다.

6단계에서 만든 맵(`maps/field_v2.json`)을 쓴다. 시뮬레이션 맵(`maps/sim_ssafy_v2.json`)은 실제 매트와 길이가 달라서 실기체에는 쓰지 않는다. 6단계 전이라도 1~3단계(카메라 자세, 색, 속도 보정)는 끝나 있어야 한다. 로봇은 패치 색과 갈림길로 위치를 알기 때문이다.

**9-1. 모터 없이 위치 추적 확인** — 손으로 바깥쪽 큰 고리를 한 바퀴 민다.

```
python3 -m agv.explore --mode passive --map maps/field_v2.json --record --view
python3 -m agv.tools.runlog data/runs/<시각>
```

- [ ] "이동(goto)" 칸에서 `다시 위치 잡음`이 0~1, `맵과 안 맞은 이벤트`가 2 이하다. 손으로 밀 때는 갈림길에서 어느 쪽으로 갔는지를 화면으로만 판단해 가끔 틀리는데, 다음 패치에서 바로잡으면(다시 위치 잡음 1) 괜찮다.
- [ ] 웹 화면의 "위치"가 지나간 패치마다 맞게 바뀐다.

**9-2. 짧은 길 고르기** — 주황 패치 조금 앞, 시계 방향. 3번 반복.

```
python3 -m agv.explore --mode goto --map maps/field_v2.json --start P_orange --to P_red --enable-motors --record --view
```

- [ ] 주황 뒤 첫 갈림길(S_a)에서 **오른쪽**(왼쪽 고리 오른쪽 변으로 내려감)을 고르고, 빨강 패치 위에서 멈춘다. `종료 이유: nav_arrived`.
- [ ] 빨강 스퍼에 들어가지 않는다(`dead_end` 없음).
- [ ] 멈춘 자리: 차체 가운데와 패치 가운데가 ±3cm 안(줄자).

**9-3. V자로 S자 선 타기** — 5단계와 같은 자리(오른쪽 아래 모서리 40cm 위, 아래를 봄). 3번 반복.

```
python3 -m agv.explore --mode goto --map maps/field_v2.json --start <V자 갈림길 노드> --to P_purple --enable-motors --record --view
```

V자 갈림길 노드 이름은 뷰어에서 오른쪽 아래 모서리의 갈라짐(◆) 노드를 눌러 확인한다(시뮬레이션 맵에서는 `S3`).

- [ ] 모서리에서 V자 쪽(오른쪽)을 고르고(`runlog` 갈림길 줄의 해석이 그 노드), 노랑을 비스듬히 지나 보라에서 멈춘다.
- [ ] 노랑 교차 뒤에 스퍼로 한 번 들어갔다 나오는 것은 정상이다(README의 알아 둘 것).

**9-4. 시작 위치 없이** — 아무 패치 앞에나 놓고 `--start` 없이 `--to P_blue`. 웹 화면의 "위치"가 처음 보이는 패치에서 "모름"에서 바뀌고, 파랑에서 멈추면 통과.

**9-5. 스퍼 끝에 주차했다가 빠져나오기** — 주황 패치 조금 앞, 시계 방향. 스퍼마다 3번씩.

```
python3 -m agv.explore --mode goto --map maps/field_v2.json --start P_orange --to D_P_orange --then P_purple --enable-motors --record --view
python3 -m agv.explore --mode goto --map maps/field_v2.json --start P_orange --to D_P_blue --then P_orange --enable-motors --record --view
python3 -m agv.tools.runlog data/runs/<시각>      # "이동(goto)" 칸의 스퍼 줄
```

- [ ] 주황(첫 번째)은 출발하자마자 패치 가운데쯤에서 왼쪽으로 제자리 회전해 스퍼를 타고(`스퍼 진입 left쪽 (옆 스퍼로 봄)`), 스퍼 끝 조금 앞에 선다.
- [ ] 선 자리: 차체 가운데가 스퍼 선 위(옆으로 ±2cm), 선 끝에서 0~4cm 앞(줄자). 차체 뒤쪽이 본선에서 얼마나 떨어졌는지도 잰다(위 README "스퍼 길이와 비켜 서기").
- [ ] 3초 뒤 후진해 본선으로 돌아와 시계 방향으로 이어 가서 `--then` 목표에 선다. `스퍼: 주차 1, 빠져나옴 1 / 후진 시작 1`, `종료 이유: nav_arrived`.
- [ ] 빨강(`D_P_red`)은 곡선에서 합류한 직후라 갈림길로 보고 들어갈 수 있다(`갈림길로 봄`). 비스듬히 서도 선 끝을 넘지 않으면 통과.

**9-6. 반대 방향과 유턴** — 맵이 양방향(`build_map` 기본)이어야 하고, 합류 노드에 `inputs`가 있어야 한다(반대로 달릴 때 그 합류가 갈림길이 됨). 2026-11-13 오후 이전 `build_map`으로 만든 맵이면 6단계의 `build_map` 명령으로 다시 만든다(주행 기록은 그대로 씀). goto를 시작할 때 `양방향, 패치 가운데·스퍼 끝에서 유턴`이 나오는지 본다. 각 3번.

```
# 반시계: 주황과 S_a 사이에 반대(도안 왼쪽)를 보게 놓고 파랑까지
python3 -m agv.explore --mode goto --map maps/field_v2.json --start P_orange --reverse --to P_blue --enable-motors --record --view
# 보라에 섰다가 주황으로: 보라 가운데에서 유턴
python3 -m agv.explore --mode goto --map maps/field_v2.json --start P_orange --to P_purple --then P_orange --enable-motors --record --view
# 빨강 스퍼에 주차했다가 되돌아 나와 주황으로(나오자마자 M_c 갈림길에서 S_a 쪽 가지)
python3 -m agv.explore --mode goto --map maps/field_v2.json --start P_orange --to D_P_red --then P_orange --enable-motors --record --view
```

- [ ] 반시계: 스퍼가 오른쪽에 보이고(`tee side=right`), 합류가 갈림길로 보여도 맞는 가지를 탄다. `다시 위치 잡음 0`.
- [ ] 유턴: 보라 가운데에서 스퍼 반대쪽으로 돌아 왔던 선을 거꾸로 탄다. 90도쯤에서 스퍼나 렌즈 선에 걸려 멈추지 않는다. `유턴: 지시 1, 완료 1`. 돌자마자 M_b(반대로는 갈림길)에서 S_a 쪽으로 간다.
- [ ] 빨강 스퍼: `스퍼에서 나가기: …쪽으로 돌아 되돌아감`, `회전 직후 바로 앞 M…에서 … 가지를 고른 채로 출발`이 나오고 주황에 선다. 엉뚱한 가지를 타면 `nav_off_route`(경로 모드) 또는 다른 길로 돌아온다.

| 유턴하다 90도쯤에서 멈추고 옆 선을 탐 | 선이 화면에서 다 사라지는 순간이 없는 자리(가까운 다른 선)다. 그 패치에서 유턴하지 않게 맵에서 `uturn`을 지우거나 다른 패치를 목표로 한다 |
| 유턴·스퍼 탈출 직후 반대 가지를 탐 | 회전 직후 그 갈림길이 화면에 어떻게 보이는지 영상으로 본다(7절). 가지가 조향 줄에서 두 줄로 안 갈라져 보이면 고른 쪽이 안 먹는다 |
| 스퍼를 못 보고 지나감(`스퍼를 못 봐서 한 바퀴 돌아 다시`) | 7절처럼 영상으로 그 패치 근처 `tee`가 나오는지 본다. 스퍼 테이프가 짧거나 흐리면 `tee.ext_k`를 낮춘다 |
| 갈림 지점보다 일찍/늦게 회전해 스퍼 옆에 섬 | `geom.ctrl_ahead_mm` 측정을 다시 한다. `runlog` 스퍼 진입 줄에 "늦음"이 크면 그 앞 패치에서 교차 판정 때문에 늦게 본 것 |
| 선 끝을 넘어가거나 너무 앞에 섬 | `recover.park_back_mm`(기본 20)를 늘리거나 줄인다. `스퍼 끝 봄: 잰 스퍼 길이`가 줄자 값과 많이 다르면 `ctrl_ahead_mm`이 틀린 것 |
| 빠져나올 때 회전 뒤 스퍼로 다시 들어감 | 4단계 표의 `back_extra_mm`(후진 거리) |
| 갈림길에서 엉뚱한 쪽 | `runlog`의 갈림길 줄: 해석 노드가 맞는지, 손해(남은 거리)가 맵 길이와 맞는지. 해석이 틀리면 그 앞 이벤트가 맵과 안 맞은 것 |
| 위치를 자주 다시 잡음 | 맵을 만든 뒤 테이프를 바꿨거나 색 보정이 달라짐. 맵을 다시 만든다 |
| 패치 앞이나 뒤에 섬 | `--stop-offset`(mm)으로 조정. 속도 보정이 안 됐으면(`runlog` 속도 보정 칸) 거리도 틀린다 |
| `nav_gave_up` | 목표로 가는 갈림길을 계속 반대로 탐: 위 "엉뚱한 쪽"과 같음 |
