# 2026-11-26 서버·통신 작업 인계

사용자가 종료를 요청해 여섯 가지 작업을 진행 중 중단했다. 다음 작업 전에
브랜치·원격과 작업 트리를 확인하고, 실물 장비의 구동은 허가하지 않는다.

## 현재까지 서버·통신 브랜치에 반영한 내용

- 팀 N01~N06, 각 4칸의 **가상** 슬롯 예약과 중복 방지, 기존 가상 경로·MQTT
  주행 연결. 실제 선반 좌표는 측정하지 않았다.
- 합성 선반 관찰→부족 판단→명시 승인→가상 작업 시작. 실제 카메라와 실측
  재고를 연결한 기능은 아니다.
- 요청 키를 새로고침 뒤에도 보존해 결과를 조회하고, 503·불명 결과에서
  재주문을 막는다. 결과 불명 주문은 가능한 경우 저장된 상세를 표시한다.
- 실물 로봇 팀 코드와 대조하고 기존 예약·복구 게이트에 인증된 정지 증거를
  기록하는 opt-in 격리 경로를 추가했다. 증거만으로 이동을 허가하거나
  점유를 해제하지 않는다.
- 로컬 관측 API 접근 제한, 격리 Mosquitto 인증·TLS·로봇별 ACL 시험,
  가상 작업 대기 순환 후보 감지와 예약 없는 우회 경로 후보, 주문 지표.
  실제 장치·운영 브로커의 보안 설정 검증은 남았다.
- 기능별 커밋은 `git log`에서 확인한다. 테스트·제약은 각 기능의 `server/docs/`
  문서를 참고한다. 가상 증거나 ACK는 실물 안전·동작의 증거가 아니다.

## 다음에 이어 할 일

1. 웹 주문→팀 6개 선반의 슬롯 예약→기존 가상 배정·MQTT→실제 Unreal
   집기·적재→재고 반영을 하나의 경로로 완성하고 종단 시험한다. 실제 Unreal
   독립 복제 프로젝트에서 24칸과 네 상품 집기·적재가 확인됐으나, 그 시험은
   위치를 직접 주입했으며 전체 웹·MQTT 종단 시험이 아니다.
2. 합성 선반 관찰을 위 완성된 종단 경로에 연결하고, 팀과 실제 비전 규격·
   재고·좌표를 확정한 후 실제 장비와 함께 별도 검증한다.
3. 실물 로봇의 작업·정지·후단 이탈·집기와 적재 결과 불명 및 재동기화
   계약을 팀과 확정해 통합한다. 실물 장비·운영 브로커 시험은 미실시다.
4. 대기 순환 관측은 일부 가상 대기에 한정되고 우회는 예약하지 않은 후보만
   반환한다. 기존 경로 세대, 점유 이전 및 발행 결과 불명 복구를 설계·시험한
   다음에만 가상 작업에 적용한다. 자동 재계획은 아직 없다.
5. 운영 환경의 장치별 인증·TLS·ACL 및 API 접근 통제를 확정하고 실제
   환경에서 검증한다. 현재 API 보호는 로컬 개발용이다.

종료 당시 Git에서 추적하지 않는 `server/tools/create_team_shelf_ue_scene.py`,
`verify_team_shelf_ue_scene.py`, `set_team_shelf_demo_camera.py`,
`team_shelf_unreal_integration_test.py`는 미완료 실험 파일이다. 원격에
포함되지 않으므로 지우거나 덮어쓰지 말고 `git status`로 확인한다.

`.venv/v3-team-shelf-full`, `.venv/team-slot-unreal-pilot`,
`.venv/team-shelf-unreal`에 있으며 Git에서 추적하지 않는다.

별도 패치 생성이 남았다. 최신 결과는
