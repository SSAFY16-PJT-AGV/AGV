# 이동 구간과 예약 자원 계산

`server.segments.plan_segment(map_data, nodes)`는 설계 문서 4장의 맵 JSON과
방향을 고려해 선택된 전체 경로를 입력받아, **출발 노드 뒤 처음 만나는
대기 노드까지** 한 번에 확보할 자원을 계산한다. 이 함수는 예약하거나
주문을 발행하지 않는다.

결과 `Segment`에는 구간 노드 `nodes`, 마지막 허가 노드 `released_until`,
그리고 원자적으로 확보해야 할 `resources`가 있다. 구간의 모든 노드와
엣지, 구간 노드가 포함된 `shared` 구역 전체를 자원으로 반환한다. 엣지
자원 ID는 양 끝 노드 ID를 정렬한 JSON 문자열로 구성하므로 반대 방향도
같은 자원으로 취급한다. 자원 표현은 서버 내부용이며 MQTT 필드를 추가하지
않는다.

## 팀 협의 전 보수적 제한

- 현재는 모든 엣지를 단일 차선처럼 독점한다. `lanes`가 2 이상이어도
  한 로봇만 같은 엣지에 진입할 수 있다. 모든 엣지의 양의 정수 `lanes`가
  필요하다.
- 마지막 목적지도 명시된 `waiting` 노드여야 구간의 종료점이 될 수 있다.
  출발 노드 자체는 다음 대기 노드로 간주하지 않는다.
- `zones`가 없거나 타입이 `waiting`·`shared`가 아닌 구역, 중복 구역 ID,
  잘못된 노드 참조, 비어 있는 공유 구역 및 유효하지 않은 엣지·경로는
  거부한다. 경로는 반복 없는 직접 연결 노드 목록이어야 한다.
- `MapGraph`의 검증을 사용하므로 엣지 형상의 양 끝은 노드 좌표와 정확히
  일치해야 한다. 허용 오차가 정해지면 팀과 함께 이 제한을 조정한다.

**자원 목록이 실제 공간을 완전하게 덮는지는 검증하지 못한다.** 예를 들어
선분 중간의 교차점이 공유 구역 노드로 표시되지 않으면 이 함수는 교차를
인식하지 못한다. 사람 또는 별도의 검증 절차가 맵의 공유 구역, 안전 구역
크기, 대기 지점, 실측 정지거리와 로봇 크기를 확인해야 한다. 원자적 예약,
물리적 후단 이탈 확인, 점유 복구와 주행 명령 인터록도 별도로 필요하다.
