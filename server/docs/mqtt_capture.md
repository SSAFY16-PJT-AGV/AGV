# MQTT 수집기

`server.mqtt_capture`는 명시적으로 실행했을 때 별도 MQTT 클라이언트로
사용자 토픽 `#`을 QoS 1로 구독해 수신 메시지를 JSONL 파일에 기록한다.
MQTT 규칙상 `#`은 `$SYS` 같은 `$`로 시작하는 시스템 토픽을 포함하지 않는다.
수집기는 어떤 토픽에도 메시지를 발행하지 않으며 FastAPI 시작 시 자동 실행되지 않는다.

## 설정과 실행

저장소 루트의 `.env` 또는 프로세스 환경 변수에서 `MQTT_HOST`, `MQTT_PORT`를
설정한다. 브로커 인증이 필요한 경우 `MQTT_USERNAME`, `MQTT_PASSWORD`,
인증 기관(CA) 인증서 파일 경로인 `MQTT_TLS_CA`를 같은 방식으로 지정한다.
인증 정보를 TLS 없이 전송하지 않으며, CA가 없거나 TLS 설정이 실패하면
브로커에 접속하지 않는다. 서버 인증서와 호스트 이름을 검증한다. 비밀번호만
지정할 수는 없다. 인증 정보 및 `.env`는 Git에 넣지 않는다. 인증 없이 로컬에서
사용할 때는 CA 없이 접속할 수 있다.

```powershell
.\.venv\Scripts\python -m server.mqtt_capture --output <새-로그-파일-경로>
```

파일을 덮어쓰지 않으므로 매 실행마다 존재하지 않는 새 경로가 필요하고,
상위 폴더는 미리 만들어야 한다. 기록 파일에는 민감한 메시지나 대용량 데이터가
들어갈 수 있으므로 저장소 밖에 보관하고 커밋하지 않는다. 종료할 때는 수집기
창에서 `Ctrl+C`를 누른다. 구독 확인 이전에 종료하거나 파일 기록 중 종료하면
불완전한 수집으로 표시한다.

브로커 연결 거절, 연결 후 10초 이내 구독 확인을 받지 못한 경우, 구독 거부 또는
QoS 1 구독 강등, 기록 실패, 연결 끊김은
수집 실패로 표시하고 종료한다. 연결 중단 뒤 자동 재연결해 연속 기록처럼
보이게 하지 않는다. 다시 시작하려면 장애를 확인하고 새 로그 파일을 지정한다.
QoS 0 메시지나 구독 전 메시지는 놓칠 수 있으며, 강제 종료나 저장장치 장애 시
마지막 레코드가 불완전할 수 있다. 이 기록만으로 모든 메시지를 놓치지 않았거나
원 발행자의 retain/QoS를 재구성할 수 있다고 보장하지 않는다.

기록 형식과 재생 시 격리 범위는 [MQTT 기록·재생 안내](mqtt_logging.md)를 참고한다.
