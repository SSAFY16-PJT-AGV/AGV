# AGV 서버·통신 진행 보고

작성 기준: 2026-11-13. 대상 브랜치: `feature/server-communication`.

## 목표와 구성

스마트 마트 AGV 관제에서 로봇 상태를 MQTT로 수신하고, 서버의 작업·예약과
디지털 트윈 연동을 검증한다. 이번 트윈 시험의 데이터 흐름은 다음과 같다.

```text
가상 로봇 상태 → 격리 MQTT 브로커 → FastAPI 서버 → WebSocket → Unreal
```

현식님은 앞서 Unreal의 맵 로딩, 로봇 이동·좌표 보간, WebSocket 상태·경로
수신 기능을 구현했다. 이번 작업은 해당 구현과 서버를 연결하고 시험한 것이며,
Unreal 이동·보간을 새로 구현한 것이 아니다.

## 진행 내용

- 기존 서버의 MQTT 상태·접속 관측, 경로 계산, 구간 예약 및 작업 관리 기반을
  확인했다. 첫 명령·후속 구간 진행과 복구는 기본 비활성인 격리 시뮬레이션
  전용이며 실물 운행 기능의 완성을 뜻하지 않는다.
- 단일 가상 로봇을 위한 로컬 WebSocket 관측 프로토타입을 추가했다.
  `agv/{id}/state`에서 받은 상태를 Unreal의 `robot.state` 형식으로 변환한다.
- 명시적으로 켠 시험 맵에서만 가상 위치를 mm에서 m로 바꾸고 방향을 전달한다.
  시험용 맵 ID가 다르거나 위치가 불완전·비정상이면 노드로 순간 이동하지 않도록
  상태를 보내지 않는다. 시험용 ID 일치만으로 실제 맵이나 좌표계 정합을 보장하지 않는다.
- MQTT 상태 수신기, 격리 시뮬레이션 이벤트 수신·명령 발행기, 기록 수집기에
  계정 인증과 TLS 설정을 적용하고 인증서 및 호스트 이름 검증을 유지했다.
  TLS 핸드셰이크 실패 시 소켓을 닫도록 보완했다.

## 검증 결과

- 2026-11-13 서버 테스트: 314개 실행, 14개 건너뜀, 나머지 통과. 별도
  Mosquitto 실행 파일이 필요한 일부 테스트는 이 환경에서 건너뛰었다.
- 가상 로봇 테스트 67개와 서버 데모 테스트 3개가 통과했다.
- 비밀번호·TLS를 사용하는 루프백 전용 aMQTT에서 가상 첫 명령과 후속 명령의
  QoS 1 전달을 확인했다. 잘못된 비밀번호, CA, 호스트 이름은 거부됐고
  인증 실패 시 미정리 소켓 경고가 재발하지 않는 것을 검사했다.
- 격리 MQTT → 서버 → Unreal Editor 직접 연동에서 `J01–N01–J02` 직선의
  연속 좌표를 보냈고, 사용자가 화면에서 부드러운 왕복을 확인했다. Unreal
  로그에서도 상태 수신과 중간 위치 보간 목표를 확인했다. 첫 좌표는 초기
  배치이며 돌아오는 방향은 회전 없이 후진하는 시험이었다.

## 실행과 주요 파일

서버 설정·실행 및 테스트 방법은 [서버 README](../README.md)를 참고한다.
트윈 프로토타입의 상세 조건은 [WebSocket 관측 제안](twin_websocket_proposal.md)에
있다. 주요 구현은 `server/mqtt_client.py`, `server/mqtt_security.py`,
`server/sim_runtime.py`, `server/twin_websocket.py`다.

## 현재 제한과 남은 일

- WebSocket과 좌표 전송은 기본 비활성 로컬 시험 기능이다. 서버의
  `robot.route` 전송, 다중 AGV 표시, 실제 좌표계·맵 정합, 코너 회전 및
  통신 단절·복구 후 트윈 동작은 검증하지 않았다.
- Unreal 인증 헤더는 별도의 로컬 테스트 사본에만 적용됐다. 원본 Unreal
  프로젝트에는 반영되지 않았다. 당시 변경을 재현할 수 있도록 브랜치
  `feature/digital-twin` 커밋 `44cc000` 기준 [인증 패치](unreal_local_auth.patch)를
  제공한다. 해당 커밋의 Unreal 프로젝트에서 `git apply --check --unidiff-zero`로
  검사한 뒤 같은 옵션으로 적용·빌드하고 서버와 같은 환경변수로 실행해야 한다.
  가상 포즈 발행 시험 스크립트와 Unreal 엔진·프로젝트 전체는 이 제출물에 없다.
- 실제 팀 브로커나 실물 JETANK 연결·안전 정지·물리 운행은 시험하지 않았다.
  MQTT 수신/발행 성공이나 PUBACK은 실제 로봇의 명령 수행을 뜻하지 않는다.
- 관측 및 시뮬레이션 브로커가 달라도 현재는 같은 MQTT 인증정보와 CA를 쓴다.
  자격정보는 커밋하지 않으며 설정 변경 후 시뮬레이션 런타임을 재시작한다.
