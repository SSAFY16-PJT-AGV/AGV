# 합성 웹 주문의 종단 시험 범위

이 시험은 별도의 로컬 aMQTT, 포트, 서버 자식 프로세스와 새 상태
디렉터리를 소유한다. 실물 장비나 실제 Unreal에 연결하지 않는다.
실행 명령은 [합성 웹 주문 시연](synthetic_web_order_demo.md)에 있다.

## 현재 확인하는 경로

- 실제 HTTP로 빨강·파랑 상품 주문을 동시에 넣고 격리 MQTT와 기존
  `SimRuntime`·두 가상 로봇을 거쳐 프로세스 내부 합성 peer의 grab/place로
  완료한다. 서로 다른 두 로봇에 배정되고 주문·pickup·선반 DB에서 각
  집기 수량 한 번 감소, pickup consumed, 슬롯 confirmed를
  확인한다. UE 토큰을 가진 다른 WebSocket이 임의 결과를 보낸 상태에서도
  합성 peer가 처리한다. 출처별 DB 및 owner 분리는 별도의 단위 시험에서도
  확인한다.
- 시험 자식 프로세스에만 동기화 지점을 설치해 합성 세계에 grab 또는
  place를 적용한 직후 서버 수신 전에 강제로 종료한다. 각각 pickup
  inflight 또는 consumed, 선반 reserved 및 allocation 점유가 보존되고,
  동일 상태 디렉터리의 재시작이 거부되는지 확인한다. 강제 종료 후
  inflight를 결과 불명으로 해석하며 이를 DB에서 자동으로 unknown으로
  바꿨다고 주장하지 않는다.
- 단위 시험은 중복 동작 ID, 잘못된 로봇·위치, 오래된 상태, 결과 거부,
  owner 무효화와 종료 경합 및 field/기존 경로의 합성 모드 거부를 다룬다.
  기존 UE 방식의 재시작·동작 시험은 별도로 실행한다.

## 별도 확인이 필요한 범위

팀 맵 합성 peer는 지원하지 않는다. pickup 결과 DB 커밋 이후 엔진 반영 전
종료, 선반 confirmed 커밋 이후
엔진 반영 전 종료, 모든 지연·중복 결과와 브로커 ACL 조합은 위 시험의
성공만으로 증명되지 않는다. 주문·pickup·allocation DB, MQTT와 메모리
세계 사이 원자성이나 실물 장비의 정지·인증·물리 재고도 입증하지 않는다.
