# 구간 예약 자료구조

`server.reservations.Reservations`는 한 프로세스 내에서 노드·엣지·구역
자원 집합을 모두 확보하거나 하나도 확보하지 않는 메모리 자료구조다.
다른 로봇이 점유한 자원이 하나라도 있으면 요청 전체를 거절한다.

`reserve(robot_id, resources)`는 성공 시 내부 예약 ID를, 실패 시 `None`을
반환한다. 같은 점유 집합의 재요청은 같은 ID를 반환한다. 기존 점유와 새
자원을 섞은 확장 요청은 거절하며, 기존 예약 ID를 덮어쓰지 않는다.
`release_after_rear_clear(robot_id, resources, lease)`는 소유자와 예약 ID가
모두 일치하는 경우에만 해제한다. 이 ID는 내부 코드용이며 MQTT 필드가 아니다.

**이 자료구조만으로 실제 주행을 허가할 수 없다.** 전체 단일 차선·교차로를
다음 대기 지점까지 자원으로 정확하게 구성하는 로직, 양방향 엣지 충돌의
공통 자원 표현, 실제 후단 이탈 이벤트와 예약 ID의 안전한 연결, 중복·지연
이벤트 처리, 서버 재시작 후 점유 복구가 아직 없다. 연결 끊김에 따라 이
자료구조가 자동으로 해제하는 동작도 없다. 예약 현황은 휘발성 메모리에만
있으며 재시작하면 사라진다. 실제 장치에 연결하기 전 위 항목의 규격과
로봇 측 안전 정지를 팀과 확인하고 검증해야 한다.
