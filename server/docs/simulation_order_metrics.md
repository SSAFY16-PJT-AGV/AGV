# 가상 주문 처리 지표

격리 웹 시연의 `GET /order-demo/api/metrics`는 기존 영속 SQLite 주문과
이벤트, 저장된 선반 상태를 한 읽기 스냅샷에서 집계한다. 로컬 시연 API의
접근 제한이 적용되고 응답은 캐시하지 않는다. 영속 장부가 없거나 조회에
실패하면 오류를 반환한다. 데이터가 없을 때 평균을 0초로 꾸미지 않는다.

- 완료 건수와 상태별 건수: DB의 현재 주문 상태를 센다.
- 배정까지 대기: 주문 생성부터 최초 `active` 기록까지의 평균이다.
- 배정 후 처리: 최초 `active`부터 `completed` 기록까지의 평균이다.
- 전체 시간: 주문 생성부터 완료 기록까지의 평균이다.
- 시간마다 표본 건수를 제공한다. 시각 누락이나 역행은 해당 주문의 시간
  계산에서 제외하고 `invalid_timestamps`에 표시한다. 이벤트 생성 순서에
  따라 최초 `active`를 고르고, 그 이후 다른 상태 갱신에서 시각이 뒤로
  간 경우도 불명으로 처리한다. 이벤트 상태 전이 순서가 장부 규칙과
  다르거나 마지막 이벤트와 현재 주문 상태가 일치하지 않아도 제외한다.
- 선반 칸의 `empty`·`occupied`·`unknown`은 마지막 저장값이며 현재
  신선도는 알 수 없다. 변화 이력이 없어 `change`는 `null`이다.

SQLite `CURRENT_TIMESTAMP`는 초 단위 UTC 벽시계다. 평균은 실제 로봇의
물리 동작 시간이나 전체 작업 중 충돌 대기 시간의 측정치가 아니고, 시간
조정·오래된 기록 또는 변경된 DB에 영향을 받을 수 있다. 서로 다른 API의
조회 결과는 같은 순간이 아니다. 이 지표는 조회 전용이며 작업 배정·점유·
복구나 실물 운행 허가에 사용하지 않는다.

조회 범위는 주문 최대 10,000개, 이벤트 최대 250,000개다. 어느 한도를
넘으면 일부만 집계해 전체인 것처럼 반환하지 않고 지표 조회를 중단한다.
