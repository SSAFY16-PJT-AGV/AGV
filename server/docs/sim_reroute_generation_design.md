# 가상 경로 변경 인계 설계 초안

현재 `GET /simulation/tasks/{task_id}/reroute-candidate`는 점유되지 않은
방향 기반 **후보**만 제공한다. 이 문서는 기존 가상 함대에서 경로를 실제로
변경하기 전에 구현하고 검증해야 할 계약을 정리한 제안이다. 아직 명령 형식,
DB 스키마, 로봇 실행기 또는 API에 적용되지 않았다. 실물 로봇의 정지·위치·
인증이나 안전을 증명하지 않는다.

## 현재 후보를 바로 발행할 수 없는 이유

- 로봇 `SimOrderInbox`와 `SimOrderExecutor`는 같은 작업의 모든 시퀀스가
  동일한 노드 경로·마지막 동작을 사용해야 하고, 작업 도중 다른 작업으로
  바꾸는 것도 막는다. 필드 실행기는 입력 방향과 경로를 매번 검증한다.
- 서버 `SegmentProgress`와 `RecoveryGate`는 최초 할당, 경로 provenance,
  모든 시퀀스, 이벤트, 현재 점유와 복구 증거의 일치를 검증한다.
  `SimOrderAuthorizer`와 `ProgressPublisher`도 이 상태를 확인한다. 한 표의
  경로만 덮으면 이 검증들이 서로 다른 이력을 보게 된다.
- 현재 대기 중 `rear_clear`의 해제 목록은 **기존 다음 구간**을 기준으로
  계산됐다. 이를 새 구간의 해제 증거로 다시 해석할 수 없다.
- MQTT PUBACK은 로봇의 수락이나 실제 이동 여부를 뜻하지 않는다. 발행 후
  연결이 끊기면 새 명령이 이미 도착했는지 알 수 없어 재발행·기존 점유
  해제·실패 확정 어느 것도 추정해서는 안 된다.

## 제안하는 인계 경계

1. 현재 작업 ID·로봇 세션·맵 fingerprint와 recovery epoch, 기존 명령
   시퀀스·payload digest·정지 방문 순번·진입 간선·이벤트 digest를 묶은
   불변 경로 세대를 둔다. 기존 이력은 변경하거나 삭제하지 않는다. 새 세대는
   부모 세대와 정지 방문에 연결하며 목적지와 종료 동작을 유지한다.
   반복 노드의 경우 노드 이름이 아닌 방문 인덱스로 구분한다.
2. 단일 SQLite writer 트랜잭션에서 신선한 수신·복구 증거 및 대상 로봇의
   가상 정지 체크포인트를 다시 확인한다. 모든 로봇의 소유권과 유휴 위치를
   포함해 새 경로의 첫 구간을 검증하고, 다른 작업과 충돌이 없을 때 기존
   점유를 보존한 채 새 구간의 추가 점유도 기록한다. 새 세대와 발행 전 의도를
   함께 기록한다. 트랜잭션 실패 시 어느 쪽도 바뀌지 않아야 한다.
3. 발행 전 **결과 불명 가능** 상태를 durable하게 기록하고 해당 세대의
   정확한 payload·digest만 한 번 전송한다. 양쪽 점유는 유지한다. 브로커
   ACK만으로 이전 점유를 해제하거나 세대 수락을 확정하지 않는다.
4. 가상 로봇은 기존 완료 이력을 검증하고 새로운 세대의 부모·정지 방문·
   방향·맵·종료 동작·순번·메시지 digest를 durable하게 검증한 뒤 수락한다.
   같은 세대의 다른 내용, 이전 세대 메시지, 중복 재실행을 거부한다. 서버가
   같은 세션의 **로봇 측 수락 증거**를 검증하기 전까지 새 세대의 전환 상태와
   기존·신규 점유를 함께 보존한다.
5. 이전 점유 중 실제로 해제 가능한 자원은 새 세대 진행에 대한 별도 가상
   정지·후단 이탈 이벤트와 점유 전환 규칙으로만 제거한다. 기존 이벤트에
   적힌 해제 목록을 임의로 재사용하지 않는다. 성공·실패·단절·재시작의
   각 경계에서도 이력 및 모든 다른 작업의 점유 검증을 유지한다.

이 설계는 재개 정책을 강제하지 않는다. 발행 결과나 로봇 수락이 불명일 때는
관련 구간을 유지하고 차단한다. 정확한 가상 수락 증거·세션 갱신 및 운영자
조치 계약을 구현·시험하기 전에는 자동 재발행하거나 전환을 되돌리지 않는다.
실물에서는 별도의 장치 인증, 위치·정지·후단 이탈 검증과 팀 합의가 필요하다.

## 구현 순서와 검증

- 기존 상태에서 미승인 우회 명령을 거부하고 pose·robot inbox·서버 점유를
  보존하는 회귀가 `server/tests/test_sim_reroute_mqtt.py`에 있다.
- 기존 경로를 건드리지 않는 세대 이력·저장소 마이그레이션 및 integrity 검증을
  먼저 추가하고 서버·로봇 양쪽의 경로 검증과 기존 재시작 읽기를 확장한다.
- 기존 점유와 새 구간의 공동 보유 및 세대 전환을 같은 SQLite 트랜잭션에서
  검증한다. 다른 작업 할당·이벤트·복구 epoch 변경과 경합해도 부분 갱신이나
  중복 소유가 없어야 한다.
- 이후에만 로봇 실행기·inbox·수신기·발행기에 새 세대와 수락 증거를 연결한다.
  가상 MQTT의 연결 상실, 수락 전후 ACK 유실, 중복·순서 역전, 세션 교체,
  DB 오류, 프로세스 재시작마다 이전·신규 점유 유지 및 재발행 차단을 시험한다.
- 최소 종단 성공 조건은 두 가상 로봇의 실제 경합에서 한 작업이 예약된
  우회 경로를 실행하고, 다른 작업도 기존 예약 절차에 따라 완료하며, 모든
  구간 인계와 중복 이벤트 후 DB 무결성이 유지되는 것이다.

현재는 위 전환을 수행하는 코드와 전체 계약이 없으므로 자동 적용은 꺼져 있다.
