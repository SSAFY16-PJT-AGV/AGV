# 팀 Navigator 제한적 반복 방문 경로 패치

`feature/field-run`의 `ef9e60001a0eb67c21fb81ea10c262eec343a4e6`를 대상으로
한 **별도 재현 패치**다. 팀 원본 브랜치에는 적용되지 않았다. 기존의 모든
반복 경로 거부 제안 `field_nav_repeat_guard.patch`와 대안 관계이며 두 패치를
함께 적용하지 않는다.

## 허용하는 범위

- 각 허가 구간 안에서도 같은 노드를 다시 방문할 수 있다. 노드 이름만이
  아닌 방문 순번을 사용하여 다음 간선과 분기를 고른다. 진입 간선과 다음 간선이
  방향·교차 및 유턴 규칙에 부합하고 현재 최선의 진입 가설이 하나여야 한다.
- 다음 허가는 이전 허가 지점에서 runner가 `hold/nav_hold`이고 해당 정지
  이벤트에 브로커 PUBACK을 받은 뒤에만 받는다. 반복 경로 정지 이벤트는
  별도의 일회성 MQTT 연결을 사용하며, 한 번만 발행하고 재연결하지 않는다.
  PUBACK 전 연결이 끊기면 서버 수신 여부를 알 수 없으므로 결과 불명으로
  남기고 재발행·다음 허가를 막는다. 전송이 이미 브로커에 도달했을 수
  있으므로 취소하거나 미수신으로 단정할 수 없다. MQTT 3.1.1의 PUBACK은
  publish ACL을 통과했거나 서버가 해당 이벤트를 받아 처리했다는 증명이
  아니며, 실제 물리적 정지의 증명도 아니다. 로봇의 로컬 완료 상태와
  서버의 작업 완료는 별개다.
- 경로에 비가시 `via`·스퍼 끝점이 있으면 반복 모드 자체를 거부한다.
  위치 가설·관측·분기가 모호하거나 gap이 발생하면
  안전 보류한다. 불확실한 정지 이벤트 발행은 오류로 남기고 자동 재발행하지
  않는다. 통신 단절로 구간 중간에 멈춘 경우 재연결 시 자동 주행 옵션이
  켜져 있어도 반복 모드에서는 재개하지 않는다. 팀 로봇의 모든 경로 기능이나
  실물 안전을 보장하는 패치는 아니다.
- 연속 경로에서 중간 노드 관측이 누락되거나 예상 밖 막다른 길이 나타나면
  이후 노드 도착으로 추정하지 않고 정지한다. MQTT 연결 단절 콜백은 큐의
  명령을 비우고 연결 세대를 변경하며, 이미 꺼낸 명령도 같은 세대에서만
  처리한다. 이는 단절 콜백이 관측되기 전 물리적 연결 상태의 증명은 아니다.
- 맵과 현재 관측으로 설명되지 않는 교차·분기는 비용만 높여 통과하지 않고
  정지한다. 정지 즉시 수행이 불가능한 회전·후진 중 단절 후 재연결되더라도
  단절 상태를 유지해 해당 동작 종료 후 대기한다. 이는 물리적 즉시 정지
  또는 복구 증명이 아니며 사람이 확인하기 전 자동 재개하지 않는다.
- 별도 이벤트 연결도 기존 사용자명·비밀번호·TLS CA를 사용한다. 브로커는
  임시 클라이언트 ID `agv-event-`와 무작위 식별자로 해당 이벤트 토픽을
  발행하도록 허용해야 한다. 브로커의 연결 인증이나 ID 정책이 연결 자체를
  거부하면 이벤트를 확인하지 못하고 대기한다. publish ACL이 이벤트를
  전달하지 않아도 MQTT 3.1.1 브로커가 PUBACK을 보낼 수 있으므로, PUBACK만
  받은 상태에서 서버가 처리했다고 가정하지 않는다. Paho 1.x 경로는 API 모양을 대역으로
  시험했으며 실제 Jetson Python 3.6 장치에서는 시험하지 않았다.
- 일회 발행은 정지 상태의 제어 루프에서 동기적으로 PUBACK을 기다리며
  3초 시간 제한을 적용한다. DNS 조회·소켓 접속·TLS 및 운영체제 스케줄링에
  따라 전체 대기가 더 길 수 있고, 기다리는 동안 그 루프의 상태 처리와
  연결 콜백 처리도 늦어질 수 있다. 실시간 제어 용도로 검증되지 않았다.
- 단절 콜백이 시작되면 같은 링크 인스턴스에는 신호가 남는다. 반복 경로는
  연결이 다시 살아나도 신호를 무시하고 출발하지 않으며, 현재 패치에는
  불명 이벤트를 해결하고 재개하는 프로토콜이 없다. 링크 교체나 프로세스
  재시작만으로 기존 작업·물리 위치가 복구됐다고 간주해서는 안 된다.
- 실제 팀 루프의 모터 명령은 통신 감지보다 먼저 적용될 수 있다. 이 패치의
  대기 처리는 실물 모터의 즉시 정지나 제동 거리를 보장하지 않는다.

기존 서버의 반복 노드·팀 맵 자동 배정 및 복구 차단은 이 패치만으로 해제할
수 없다. 현재 실물의 인증된 위치·방향, 후단 이탈·정지 증명, 프로세스 재시작
후 명령·방문 이력 복구 및 예약 원자성 연결은 별도 검증이 필요하다.

## 격리 재현

아래 시험은 팀 소스에서 매번 새 임시 사본을 만들고 패치한다. 팀 원본과
하드웨어를 수정하거나 동작시키지 않는다. 별도로 `numpy`와 `opencv`가 설치된
가상 매트 의존성 폴더가 필요하다.

```powershell
$env:TEMP = (Resolve-Path .venv).Path
$env:TMP = $env:TEMP
$env:AGV_FIELD_REPO = 'C:\팀코드경로'
$env:AGV_FIELD_MAT_DEPS = 'C:\가상매트의존성경로'
.\.venv\Scripts\python -m unittest server.tests.test_field_navigator_sequence -v
```

합성 분기·교차·유턴·조기 연장·중복·관측 누락·발행 오류 사례와 팀 가상
매트의 `P_orange → P_purple → P_orange` 두 구간 왕복(세 가지 시드)을
실행한다. 유턴 직전 스퍼 판정값이 남아 유턴 후 실제 감지된 M1 분기를
스퍼로 잘못 기록하던 문제를, 유턴 회전 완료 시 해당 오래된 판정만 비워
수정했다. 이후 세 시드에서 분기 검출 이벤트와 두 도착을 확인했다. 관측이
실제로 누락된 경우에는 이를 추측하지 않고 안전 정지한다. 테스트 입력의
로봇/관측은 가상이며 실물 주행 결과가 아니다.

같은 허가 구간에서 위 왕복 전체를 수행하는 가상 매트 시험도 세 시드에서
완료했다. 같은 교차점을 두 번 정지점으로 지정하는 별도 시험에서는 지연된
관측 때문에 첫 교차점을 지난 뒤 정지할 수 있다. 이 경우 뒤늦게 확정된
관측과 모순되면 완료 이벤트를 만들지 않고 오류로 정지한다. 실제 안전 대기
지점 또는 물리적 정지를 증명하는 기능은 아니며, 예약 해제 근거로 실물
장치에 사용하지 않는다.
