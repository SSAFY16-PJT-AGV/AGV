# 팀 Navigator 제한적 반복 방문 경로 패치

`feature/field-run`의 `ef9e60001a0eb67c21fb81ea10c262eec343a4e6`를 대상으로
한 **별도 재현 패치**다. 팀 원본 브랜치에는 적용되지 않았다. 기존의 모든
반복 경로 거부 제안 `field_nav_repeat_guard.patch`와 대안 관계이며 두 패치를
함께 적용하지 않는다.

## 허용하는 범위

- 전체 경로에 같은 노드가 있어도 **각 허가 구간**에는 중복이 없어야 한다.
  각 구간은 그 구간의 명시적 간선만 사용한다. 진입 간선과 다음 간선이
  방향·교차 및 유턴 규칙에 부합하고 현재 최선의 진입 가설이 하나여야 한다.
- 다음 허가는 이전 허가 지점에서 runner가 `hold/nav_hold`이고 해당 정지
  이벤트를 로컬에서 처리한 뒤에만 받는다. 이 검사는 실제 물리적 정지의
  증명이 아니며, 이벤트 MQTT 큐 수락은 브로커 ACK나 서버 처리 증명이 아니다.
- 구간 안에 반복 방문이 있거나 경로에 비가시 `via`·스퍼 끝점이 있으면
  반복 모드 자체를 거부한다. 위치 가설·관측·분기가 모호하거나 gap이 발생하면
  안전 보류한다. 불확실한 정지 이벤트 발행은 오류로 남기고 자동 재발행하지
  않는다. 통신 단절로 구간 중간에 멈춘 경우 재연결 시 자동 주행 옵션이
  켜져 있어도 반복 모드에서는 재개하지 않는다. 팀 로봇의 모든 경로 기능이나
  실물 안전을 보장하는 패치는 아니다.
- 연속 경로에서 중간 노드 관측이 누락되거나 예상 밖 막다른 길이 나타나면
  이후 노드 도착으로 추정하지 않고 정지한다. MQTT 연결 단절 콜백은 큐의
  명령을 비우고 연결 세대를 변경하며, 이미 꺼낸 명령도 같은 세대에서만
  처리한다. 이는 단절 콜백이 관측되기 전 물리적 연결 상태의 증명은 아니다.

기존 서버의 반복 노드·팀 맵 자동 배정 및 복구 차단은 이 패치만으로 해제할
수 없다. 현재 실물의 인증된 위치·방향, 후단 이탈·정지 증명, 프로세스 재시작
후 명령·방문 이력 복구 및 예약 원자성 연결은 별도 검증이 필요하다.

## 격리 재현

아래 시험은 팀 소스에서 매번 새 임시 사본을 만들고 패치한다. 팀 원본과
하드웨어를 수정하거나 동작시키지 않는다. 별도로 `numpy`와 `opencv`가 설치된
가상 매트 의존성 폴더가 필요하다.

```powershell
$env:TEMP = (Resolve-Path .venv).Path
$env:TMP = $env:TEMP
$env:AGV_FIELD_REPO = 'C:\팀코드경로'
$env:AGV_FIELD_MAT_DEPS = 'C:\가상매트의존성경로'
.\.venv\Scripts\python -m unittest server.tests.test_field_navigator_sequence -v
```

합성 분기·교차·유턴·조기 연장·중복·관측 누락·발행 오류 사례와 팀 가상
매트의 `P_orange → P_purple → P_orange` 두 구간 왕복(세 가지 시드)을
실행한다. 이 매트에서는 유턴 뒤 M1 분기 관측이 누락될 수 있다. 이 경우
두 번째 도착을 확인하지 않고 안전 정지하는 것이 기대 결과이며, 실제 팀
runner의 해당 반복 경로 완주를 지원하거나 검증했다는 뜻이 아니다. 테스트
입력의 로봇/관측은 가상이며 실물 주행 결과가 아니다.
