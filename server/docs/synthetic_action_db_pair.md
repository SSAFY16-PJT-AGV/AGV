# 합성 동작 DB 쌍의 격리 생성·조회

`SyntheticActionDbPair`는 주문/선반 DB와 pickup DB를 새 디렉터리에
생성하고 같은 합성 실험의 쌍인지 확인하는 **기초 경계**다. 두 DB는
별도의 SQLite 파일과 트랜잭션을 사용한다. 아직 합성 peer, 웹 주문,
실제 발행기 또는 재고 업데이트와 연결되지 않았고, 물리 세계나 실제
로봇의 신원·위치·수락·집기 결과 또는 운행 안전을 증명하지 않는다.

`create_new`는 이미 있는 디렉터리를 절대 재사용하지 않는다. 지정한
소문자 32자리 hex world, 별도 무작위 pair ID와 주문 DB creation ID,
pickup DB 고유 creation ID를 양쪽 DB와 완료 표식에 기록한다. 생성 중
오류나 프로세스 종료가 발생해도 생성된 파일을 지우거나 기존 파일을
덮어쓰지 않으며, 같은 디렉터리의 재생성은 실패한다. 표식 생성 전
중단이나 불완전한 표식은 검증도 실패한다. 표식이 쓰인 뒤 최종 검증에서
오류가 나면 호출자에게는 생성 실패가 반환되지만, 남은 DB와 표식 자체가
일관된 경우 이후 읽기 검증은 성공할 수 있다. 이 경우에도 결과는 항상
`operable=False`이고 재개할 수 없다. 별도 실험은 새로운 경로를 사용한다.
완료 표식은 두 DB의 단일 원자 커밋이나 정전 후 저장 장치의 내구성 보장이 아니다.

생성자는 기존 UE 저장소를 마이그레이션하지 않는다. 합성 DB의 source
스키마 버전은 주문 3, pickup 2이고 기존 UE 버전은 주문 2, pickup 1이다.
쌍과 관련된 값을 서로 비교하며, 기존 주문 DB가 보유한 pickup creation ID,
두 DB의 world, 카탈로그, pickup 대응, source/version도 대조한다.

반환된 객체는 `operable=False`이고, 쓰기 가능한 저장소 객체를 보관하지
않는 전용 읽기 뷰를 제공한다. 각 조회는 SQLite `mode=ro` 연결을 열며
주문 제출, pickup 세션 시작 등 쓰기 메서드를 제공하지 않는다. 읽기 전에
쌍의 두 DB를 재검사하며
같은 내용으로 교체된 파일도 현재 객체의 파일 식별자와 다르면 거부한다.
`close()` 후 이전에 얻은 읽기 핸들도 사용할 수 없다. 이것은 제품 workflow
통합을 위한 변경이 아니다. 두 DB의 검사 후 새로운 연결에서 쓰면 그 사이
다른 DB가 변경될 수 있어, 쌍을 통한 쓰기는 양쪽 상태를 보호하는 별도
경계가 구현되기 전까지 지원하지 않는다.

`pair_id`, `world_id`, `order_creation_id`는 읽기 전용 생성 식별자다.
`close()` 후에도 외부 보관과 진단을 위해 읽을 수 있지만, 해당 DB가 현재
유효하거나 사용 중이라는 뜻은 아니다. `operable`은 종료 전후 모두 읽기
전용 `False`다.

생성 중과 객체 수명 동안 주문 DB의 기존 OS 소유권 잠금을 보유한다. 같은
잠금에 참여하는 다른 생성·검사기는 동시에 들어올 수 없다. 외부에서 이
잠금을 무시하고 파일을 바꾸는 다른 프로세스를 차단하거나, 파일 교체의
모든 경합·백업 롤백·유효한 DB 내용의 변조를 탐지한다고 주장하지 않는다.
각 SQLite의 읽기는 별도 트랜잭션과 별도 시점의 스냅샷이다. 결과는 읽는
동안 변경될 수 있으며 pair ID와 world ID는 인증 수단이 아니다. Python
내부 객체에 대한 악의적 접근이나 직접 DB 파일을 여는 행위도 막지 않는다.

종료 후 `inspect_existing`은 호출자가 DB 밖에 보관한 예상 pair ID와
world ID를 요구한다. 검증 결과는 `operable=False`이며, DB는 읽기 전용으로
연다. `open_existing`은 검증 성공 후에도 유실된 합성 세계를 되살리지 않고
거부한다. 현재는 서버 재시작 후 자동 재개를 지원하지 않는다.

```powershell
$env:TEMP = (Resolve-Path .venv).Path
$env:TMP = $env:TEMP
.\.venv\Scripts\python.exe -m unittest server.tests.test_synthetic_action_db_pair -v
```
