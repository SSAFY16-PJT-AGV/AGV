# 디지털 트윈 WebSocket 관측 제안

팀 협의 전, 단일 가상 로봇의 로컬 관측 연결을 확인하기 위한 임시 제안이다.
설계 문서 v0.3의 MQTT 통신을 대체하거나 실제 로봇의 운행을 승인하지 않는다.
Unreal 클라이언트가 이미 사용하는 `/ws/digital-twin`과 `robot.state` 형식을
활용한다. 좌표계·각도·배터리 단위와 여러 로봇의 표시 방식은 미확정이다.

- 기본적으로 비활성화하며, 명시적으로 지정한 `sim-` ID 한 개만 로컬 접속자에게 보낸다.
  ID 접두사만으로 가상 로봇이나 네트워크 격리는 보장되지 않으므로 반드시 실물과
  분리된 브로커 및 가상 로봇을 별도로 준비해야 한다. 루프백 외 접속은 거부한다.
- Origin이 없는 로컬 클라이언트는 기존처럼 토큰 없이 접속 가능하다. Origin이
  있으면 정확히 하나의 `http://127.0.0.1` Origin과 정확히 하나의
  `X-AGV-Twin-Token`이 필요하다. 토큰은 서버 환경변수 `AGV_TWIN_UNREAL_TOKEN`과
  일치하는 32~128자의 영문 대소문자·숫자·`_`·`-`여야 한다. 미설정, 불일치,
  다른 Origin이나 중복 헤더는 거부한다. 새 토큰은 암호학적으로 안전하게
  생성하고 서버와 Unreal 프로세스에 전달하며 소스·URL·로그에 남기지 않는다.
  현재 Unreal 헤더 지원은 `D:\AGV-Twin-Validation` 테스트 사본에만 있으며
  현식님의 원본 프로젝트에는 반영되지 않았다. 해당 시험 사본의 변경은
  `feature/digital-twin` 커밋 `44cc000` 기준 [인증 패치](unreal_local_auth.patch)로
  제공한다. 해당 커밋의 Unreal 프로젝트 루트에서 `git apply --check --unidiff-zero`
  다음에 패치 경로를 지정해 검사하고, 같은 옵션으로 적용·빌드해야 한다.
- 이 토큰 정책은 Origin이 없는 로컬 프로그램을 인증하지 않는다. 동일 계정의
  프로세스가 환경변수를 읽을 가능성도 있으므로 신뢰할 수 없는 사용자나 외부
  네트워크에 대한 보안으로 취급하지 않는다. 브로커 격리를 별도로 확인한다.
- MQTT 연결과 구독이 준비된 상태에서 새로 수신한 상태 중 수신 메시지에
  retain 플래그가 표시되지 않은 것만 전송한다. MQTT의 retain 플래그는 수신
  방식에 관한 정보이므로 원본 발행이 비보관이었거나 상태가 안전하다는 증거는 아니다.
  연결 시 오래된 스냅샷, retained 상태, 중복 폴링과 연결 끊김 전 값은 재전송하지 않는다.
- 기본 모드에서는 `agv_id`, `status`, `current_node`, `battery`만 전달한다. `last_node`를
  `current_node`에 대응하는 임시 가정이며 노드 ID와 맵 버전은 별도 검증이 필요하다.
  상태·노드·배터리가 모두 유효하지 않으면 메시지를 보내지 않는다. 현재 트윈이
  누락된 상태와 배터리를 빈 문자열과 0으로 표시하기 때문이다.
- 선택적 가상 위치 시험: 서버 환경변수 `AGV_TWIN_POSE_MAP_ID`가 비어 있으면
  기존 노드 관측만 전송한다. `twin-validation-v1`로 설정할 때만 같은
  `map_id`를 가진 MQTT 상태의 `pose.x`, `pose.y`, `pose.th`를 전송한다.
  이 ID는 테스트용 표시이며 일치 자체가 맵이나 좌표계 검증을 뜻하지 않는다.
  비어 있지 않은 다른 설정값, 다른 ID, 필드 누락 또는 잘못된 값이면 그 상태
  메시지 전체를 보내지 않는다. 좌표를 빼고 노드만 보내면 Unreal이 노드로
  순간 이동할 수 있기 때문이다.
- 시험 입력은 `pose.x`·`pose.y`를 mm, `pose.th`를 도(degree)로 해석하고
  WebSocket `data.x`·`data.y`를 m, `data.yaw`를 도로 보낸다. 예를 들어
  `{x: 1500, y: 2000, th: 90}`은 `{x: 1.5, y: 2.0, yaw: 90}`이 된다.
  x/y/th는 모두 유한한 숫자여야 하며 불리언은 허용하지 않는다. 시험 보호
  한계는 각각 x/y ±1,000,000 mm, 각도 ±3,600도다. 이 한계는 맵 경계나
  안전 범위가 아니다.
- 시험 발행기의 좌표계와 Unreal 창고 맵은 같은 원점·축·각도 방향이라고
  가정한다. 다른 맵이나 실물의 좌표계 정합은 검증되지 않았으며 팀 합의가
  필요하다. Unreal은 첫 pose를 초기 위치로 즉시 배치하고, 이후 유효한 pose를
  보간하므로 초기 배치를 연속 주행으로 해석하지 않는다. `robot.route`는
  변환하거나 전송하지 않으며 이 시험은 실물 위치·경로·운행을 검증하지 않는다.
- 전송 값은 로봇의 안전이나 주행 권한을 증명하지 않는다. MQTT·브라우저 보안,
  외부 네트워크 연결 및 다중 AGV 지원은 이 제안 범위 밖이다.
