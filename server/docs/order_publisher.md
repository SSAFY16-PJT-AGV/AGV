# 주문 발행 계층: 격리 모의환경 전용

`server.order_publisher.OrderPublisher`는 설계 문서 3장의 주문을
`agv/{id}/order` 토픽에 MQTT QoS 1, retain 없음으로 보내는 독립 계층이다.
기본값은 비활성화이며 `enabled=True`를 명시하지 않으면 발행하지 않는다.
현재 발행 대상은 `sim-`으로 시작하는 가상 로봇 ID로만 제한한다. 이 ID
접두사만으로 물리적 네트워크 격리가 증명되지는 않으므로, 실물 장비나
실물 브로커와 연결되지 않은 별도의 격리 환경에서만 사용해야 한다.

전달하는 최상위 JSON 필드는 설계의 `order_id`, `seq`, `map_id`, `nodes`,
`released_until`, `action_at_end` 여섯 개만 허용한다. `released_until`은
`nodes`의 원소여야 하고 `action_at_end`는 비어 있지 않은 `type`을 가진
객체여야 한다. 이 검증은 **맵·경로·구간 소유권이 유효함을 증명하지 않는다.**
payload 크기와 중첩 깊이, 로봇 ID 길이에도 임시 상한이 있으므로 팀의 실제
메시지 규격이 확정되면 함께 확인해야 한다.

`validate_order(robot_id, order)`는 브로커에 접근하거나 발행하지 않고 대상과
주문 JSON 구조만 검사하며, 오류가 있으면 `ValueError`를 발생시킨다. 예약과
작업 상태를 영속 확정하기 전 불량 입력을 걸러내는 용도다.
`publisher.validate(robot_id, order)`는 여기에 비활성화 여부, 전송 객체의
사용 여부, 자동 재연결 설정과 현재 연결 여부까지 검사한다. 어떤 검사도 메시지를
보내거나 객체의 1회 사용 기회를 소비하지 않는다. 이 확인 직후 연결이 변할 수
있으므로, 확인 성공이 나중의 발행 성공을 보장하지 않는다.

```python
from server.order_publisher import OrderPublisher

# client는 격리된 브로커에 이미 연결한 전용 Paho 클라이언트다.
# 생성 시 reconnect_on_failure=False를 지정해야 한다.
publisher = OrderPublisher(client, enabled=True)
publisher.validate("sim-robot1", order)
# 호출자는 이후 발행 시도를 영속 저장한 다음 발행해야 한다.
info = publisher.publish("sim-robot1", order)
```

`publish()`가 반환하는 `MQTTMessageInfo`의 성공 결과는 **로컬 큐에 넣은
결과**다. 브로커의 PUBACK도 로봇이 명령을 받았거나 실행했다는 증거가
아니다. QoS 1은 중복 전달될 수 있다. 로봇 측 중복 방지, 명령 승인·도착
확인 및 서버의 장애 복구 규약은 별도로 합의해야 한다.

## 단절과 불확실한 전송

Paho 2.1은 QoS 1 전송 도중 연결이 끊기면 오류를 반환해도 메시지를 내부
큐에 남길 수 있고, 재연결하면 자동으로 재전송할 수 있다. 이 모듈은 Paho
2.1의 내부 `_reconnect_on_failure`가 명시적으로 `False`인 클라이언트만
허용한다. 공개 getter가 없어 버전 고정에 의존하며, 향후 Paho 변경 시
재검증이 필요하다. 발행 객체는 실제 발행 시도를 한 번만 허용한다. 그러나
이 검사만으로 클라이언트의 **수동 재연결, 다른 코드의 재사용, 이미 브로커에
도착한 메시지**까지 차단할 수는 없다.

실제 사용자는 전용 클라이언트를 사용해야 하며, 단절·전송 오류 또는 결과가
불확실한 경우 다시 연결하거나 재사용하지 말고 클라이언트를 폐기해야 한다.
오류 또는 타임아웃이 발생해도 주문이 로봇에 전달되지 않았다고 단정하거나
예약을 해제하면 안 된다. 재시작·재연결 시 점유와 주문을 안전하게 복구하기
전에는 재발행하지 않는다.

현재 이 계층은 SQLite 예약·작업 저장소와 연결되어 있지 않다. 실제 통합
호출자는 주문을 보내기 **이전에** 작업·구간 예약과 고유 주문 ID·시퀀스,
발행 시도 상태를 영속 저장하고, 충돌·중복·불확실 전송 처리 및 수신 확인
규약을 구현해야 한다. 현재 구현은 실물 로봇에 대한 주행 허가 기능이 아니다.
