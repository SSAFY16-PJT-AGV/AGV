# 격리 가상 작업 조사 참고 기록

`SimInvestigationNotes`는 가상 작업을 조사하는 동안 정해진 분류와 당시 DB
메타데이터를 같은 시뮬레이션 SQLite에 남기는 별도 구성요소다. 이 기록은
실물 로봇에 대한 확인·위치·정지·이탈 증거나 작업 수행의 증명이 아니다.
기록하거나 조회해도 작업, 발행 상태, 점유, 재고와 복구 게이트를 바꾸거나
MQTT를 발행하지 않는다. 선택적 로컬 HTTP 연결은
`server/docs/sim_investigation_notes_api.md`를 참고한다.

호출자는 시작된 격리 `SegmentProgress`, 그 복구 게이트와 명시적 가상
로봇·작업 대응을 주고 `simulation=True`를 지정한다. `initialize()`는
같은 DB에 별도 테이블을 추가하며 기존 작업 테이블을 대체하지 않는다.

```python
from server.sim_investigation_notes import SimInvestigationNotes

notes = SimInvestigationNotes(progress, {'sim-r1': ['T1']}, simulation=True)
notes.initialize()
record = notes.record('T1', '19e8327bd02e4c2583f745a8b1bd9c60', 'connection')
page = notes.list('T1', after_id=0, limit=20)
```

위 ID는 예시다. 실제 호출자는 요청마다 새 무작위 32자리 소문자 hex를
생성하고, 동일 요청이 불확실할 때만 같은 ID를 재사용한다. 같은 ID·작업·
분류의 재시도는 원래 기록을 반환하며, 같은 ID에 다른 작업이나 분류를
넣으면 거부한다. 분류는 `position`, `connection`, `action`, `other`만
허용한다. 이 값은 사람이 고른 **조사 주제**이며 정지 확인이나 실제 사건의
진위를 나타내지 않는다. 자유 텍스트·작성자 이름·비밀번호·토큰 입력은 없다.
ID나 맵·자원 이름에 개인정보·비밀정보를 넣지 않는다. 이미 DB에 저장된
작업·맵·로봇·자원 ID가 참고 스냅샷에 복제되므로, 이들을 포함한 DB의 접근·
보존 정책은 별도로 정해야 한다. ID 형식만으로 내용이 무작위이거나 민감
정보가 없다는 것을 증명할 수 없다.

기록 당시 작업 상태, 설정된 가상 로봇 ID, 기존 명령 전송 상태와 점유 자원은 삽입과 같은 SQLite
쓰기 트랜잭션에서 읽는다. 스냅샷은 길이·자료형과 로봇 대응만 검사한 DB
메타데이터이며 주문 본문·맵·이벤트의 정합성이나 외부 상태를 검증하지
않는다(`integrity: not_checked`). 기록된 설정 로봇 또는 현재 DB의 배정 로봇이
현재 작업 대응과 다르거나 외래 키 고아가 발견되면 이전 기록의 재조회·재시도를
거부한다. `ASSIGNED` 작업은 배정과 최초 주문이 모두 존재해야 하며, 배정과
최초 주문 중 하나만 있는 상태도 거부한다. 배정 전 `PENDING`은 조회할 수 있다.
이는 모든 DB 내용의 신뢰성을 검증한다는 뜻은 아니다. 목록은 작업당 최대 1,000건, DB 전체 최대
10,000건이며 용량 초과 시 이전 기록을 삭제하지 않고 새 기록을 거부한다.
한 번에 최대 20건, 스냅샷당 최대 64 KiB이고 주문 100개·점유 500개까지
기록하며 더 많으면 각각 `orders_truncated`·`occupancy_truncated`로 표시한다.
과도하게 긴 값이나 손상된 스냅샷은 그대로 반환하지 않는다.

서버 UTC 시각은 마이크로초를 포함한 고정 UTC ISO 형식으로 기록·검사한다.
이는 서버 시계의 관측이며 사건 발생 시각·기록 순서·신원 증명이
아니다. 공통 Bearer 토큰과 루프백 접속은 개인 작성자 신원을 제공하지 않는다.
API 수준에서 수정·삭제를 제공하지 않을 뿐, DB 파일의 직접 수정·삭제, 과거
백업으로 되돌리기나 손상은 막지 못한다. 따라서 위변조 방지 감사 기록이나
법적 증거로 사용하지 않는다. 재시작 시 새 복구 세대는 과거 기록을 조회할
수 있지만 오래된 게이트 인스턴스는 새 기록을 쓸 수 없다. 이 기록 자체는
복구 승인이 아니며, DB/파일 식별 검사와 기록의 생존은 별도 백업·운영 환경의
한계가 있다.

기록은 게이트의 작업 잠금을 점유하지 않고 SQLite 트랜잭션에서 현재 세대를
검사한다. 쓰기는 SQLite 쓰기 잠금을 얻은 뒤 세대를 확인하므로 그 사이 새
세대가 커밋되면 거부된다. 조회는 트랜잭션 스냅샷의 세대를 확인하므로 WAL
환경에서 조회 도중 새 세대가 커밋될 수 있으며, 응답은 그보다 앞선 시점의
참고 정보일 수 있다. 이 읽기나 기록은 차단 상태를 해제하지 않는다. 동일
스레드의 게이트 트랜잭션 또는 직렬화 구간에서 중첩 호출은 거부한다.

```powershell
$env:TEMP = (Resolve-Path .venv).Path
$env:TMP = $env:TEMP
.\.venv\Scripts\python.exe -m unittest server.tests.test_sim_investigation_notes -v
```
