# PR #59 실물 로봇 연동 검토

기준: 2026-11-25에 확인한 [PR #59](https://github.com/SSAFY16-PJT-AGV/AGV/pull/59)의
`45a6318d1706f3929a98e52929bc395667f11128`과 로봇 `feature/field-run`의
`0e00569`. 이후 변경은 다시 대조해야 한다. PR #59는 별도 브랜치이며
`feature/server-communication`에 합쳐진 것이 아니다.

## 확인한 문제

1. **정지 상태 캐시와 단절:** `PhysicalStateWatcher`는 수신 시각을 저장하지만
   상태 신선도를 확인하지 않고 같은 상태로 정지 증명을 반복 갱신한다. 격리된
   대역 시험에서 상태 한 건만 수신한 뒤 0, 16, 32초에 증명이 세 번 만들어졌다.
   MQTT 연결 단절을 처리하는 수신기의 무효화와 감시기의 재증명도 경합할 수 있다.
   상태 갱신 시간 제한만으로 모든 발행·복구 경합이 해결되지는 않는다.
2. **물리 로봇의 반복 방문:** 팀 로봇은 경로 간선을 집합으로 취급하여 같은
   노드 방문 순서를 잃을 수 있다. 팀 로봇 코드 대역에서 `A→B→C→B→D`를
   `B→D`로 건너뛰는 사례를 확인했다. 기존 순번 패치는 팀 로봇 원본에 적용된
   것이 아니다. PR #59의 플래너는 반복 경로를 허용한다.
3. **초기 상태와 우회 경로:** 시작 시 실시간 세션 문자열은 읽지만 설정한
   시작 위치·맵·정지 상태의 일치는 검증하지 않는다. 수동 복구 API 역시 별도의
   실물 상태 확인 없이 증명을 시도할 수 있다. 새 세션과 이전 상태 처리의 경합도
   감시·인계·발행 경계에서 함께 다뤄야 한다.
4. **해제 자원 계약:** #48 댓글은 `cleared_resources`를 참고용으로 보고 서버가
   맵으로 계산한다고 설명하지만 현재 진행·인계 코드는 로봇 보고값과 계산값의
   정확한 일치를 요구한다. 불일치 시 진행을 거부하는 동작이므로 팀과 계약을
   맞춰야 한다.

## 인계 조건과 한계

끝 동작이 `none`인 경우 PR의 구간 인계는 최종 이벤트 적용, 기존 작업의 증명,
최종 노드 점유, 새 구간 충돌 검사와 점유 이전을 DB 트랜잭션 안에서 확인한다.
다만 오래된 정지 증명을 그 입력으로 받아들이면 실제 정지를 확인한 것은 아니다.
`load`/`unload` 인계에는 별도의 결과 규약이 필요하다.

상태 신선도·온라인 상태·세션·초기 위치를 확인하고, 단절·상태 변경 시 증명과
명령 세대를 무효화하여 재시도·인계·발행과 함께 경합 시험해야 한다. 기존 점유는
불명 상태에서 유지해야 한다. 실제 기기의 인증·TLS·ACL과 물리 정지·후단 이탈
검증도 별도다. MQTT PUBACK이나 로봇 자기 보고만으로 이들을 증명할 수 없다.

검토용 후속 변경은 [PR 기반 별도 브랜치](https://github.com/SSAFY16-PJT-AGV/AGV/tree/feature/physical-review-safeguards)에서
실물 런타임 시작과 실물 반복 경로를 차단한다. 이는 실물 운행을 허용하는 수정이 아니다. 기존 PR 원본은 자동으로
변경되지 않는다. 가상 매트의 `physical-*` 통합 시험도 차단을 해제하기 전에는
정상 운행 시험으로 실행할 수 없다.
