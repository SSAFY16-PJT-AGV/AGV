# SQLite 작업 상태 저장소

`server.task_store.SqliteTaskStore`는 작업 ID와 상태를 SQLite 파일에 기록한다. 서버 DB 제품은 설계 문서에서 지정하지 않아, 이 구현에서는 Python 표준 라이브러리의 SQLite를 내부 저장소로 선택했다. 실제 배포 환경과 DB 제품은 팀에서 합의해야 한다.

호출자는 데이터베이스 파일 경로를 제공하고 먼저 `initialize()`로 테이블을 생성한다. 이후 `create(task_id)`, `get(task_id)`, `transition(task_id, expected, target)`을 사용할 수 있다. 초기화는 기존 작업을 지우지 않지만 기존 스키마의 마이그레이션이나 백업은 수행하지 않는다. 파일 위치는 배포 환경에서 관리하며 Git에 커밋하지 않는다.

상태 전이와 오류 종류는 `server.tasks`의 독립 상태 모델을 따른다. 각 쓰기는 SQLite 트랜잭션과 별도 연결을 사용한다. 현재 상태가 기대 상태와 다르면 전이하지 않고 `StateConflictError`를 발생시킨다. 작업 ID는 SQL 매개변수로 전달한다.

동일 DB에 `allocation_outbox`가 있고 해당 작업의 주문 상태가 `uncertain` 또는
`acked`라면, 물리 이벤트와 취소·복구 규격을 합의하기 전까지 모든 상태 전이를
`StateConflictError`로 거절한다. `pending` 주문의 취소는 허용되지만 이후 발행은
배정 저장소에서 거절하며 점유는 보존한다. 예전 DB에 outbox 표가 없다면 기존
상태 전이 동작을 유지한다.

`FAILED`, `CANCELLED`는 예외 전이 규칙이 확정되기 전의 임시 가정이다. 저장된 상태만으로 로봇의 정지, 작업 성공, 물품 인도, 예약 해제를 증명하지 못한다. MQTT 이벤트의 진위·순서·중복, 물리 안전 인터록, 서버 기동 시 복구 절차는 이 저장소에 연결되어 있지 않다. 구간 점유는 같은 DB의 별도 배정 저장소가 관리하지만 실제 후단 이탈이나 안전한 해제는 아직 구현되지 않아 실물 주행 허가에 사용하면 안 된다.
