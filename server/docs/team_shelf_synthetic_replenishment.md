# 팀 선반 가상 재고 부족과 보충 승인

이 기능은 팀 6선반 가상 웹 시연에서 **Unreal이 보낸 마지막 선반 스냅샷을
6개 합성 관찰 프레임으로 변환**해 재고 부족을 보여준다. 실제 카메라·비전
모델·물리 재고를 읽지 않는다. Unreal 상태도 임의의 가상 배치이며 실제
상품 위치나 수량을 증명하지 않는다.

## 화면에서 사용하기

1. `server/docs/team_shelf_web_demo.md`의 격리 브로커·서버·팀 선반 Unreal
   실행 절차를 따른다. 두 가상 로봇과 Unreal 소유자가 준비돼야 한다.
2. 웹의 **가상 선반 확인**을 누른다. 각 상품을 부족, 충분, 확인 불가,
   상품 불일치 중 하나로 표시한다. 웹 기준은 목적 선반에서 해당 상품이
   한 개 미만일 때 부족이다.
3. 위 상품 선택에서 부족한 상품을 고르고 **선택 상품 보충 승인**을 누른다.
   자동 승인은 하지 않는다. 정상 접수되면 기존 웹 주문과 같은 가상 함대
   배정·구간 예약·MQTT·Unreal 집기·적재 경로를 사용한다.
4. 결과가 불명이거나 응답이 유실되면 화면의 기존 요청 확인을 사용한다.
   브라우저가 저장한 요청 키로 조회하며 자동으로 다시 주문하지 않는다.

캡처는 원본 Unreal 스냅샷을 서버가 수신한 시각부터 5초 안에서만 사용한다.
원본이 오래됐다면 같은 연결에서 새 스냅샷을 요청하고 응답을 잠시 기다린다.
갱신에 실패하면 확인 불가로 처리하며 다시 확인할 수 있다. 서버 시계가
거꾸로 가거나 연결·스냅샷 세대가 바뀌면 기존 결과는 사용할 수 없다.
합성 캡처가 오래된 원본을 새 관측으로 만들지 않는다. 이 수신 시각은
Unreal의 가상 메시지에 대한 것이며 실물 카메라 촬영 시각은 아니다.
캡처 결과는 최대 5초간 유효하지만, 원본이 먼저 만료되거나 새 원본이
수신되면 더 빨리 무효가 된다. 화면은 4.5초 뒤 승인 버튼을 끄며,
그 사이에도 점유·연결·관측이 변하면 서버가 승인을 거부할
수 있다. 픽업 지점 D01/N01이나 관련 구간을 다른 가상 작업이 사용 중인
경우에는 자동 대기하지 않고 승인 전에 거부하므로 나중에 다시 관찰하고
승인해야 한다. 점유된 칸이나 관측이 불명인 칸은 빈 칸으로 간주하지 않는다.
선반에 다른 상품이 있으면 부족으로 간주하지 않는다.

## 로컬 API

두 API는 기존 웹 주문과 동일한 로컬 Host·Origin 제한을 적용한다. 외부
사이트나 실물 장비가 사용하는 운용 API가 아니다.

- `POST /order-demo/api/synthetic-shortages`, JSON `{"threshold": 1}`:
  현재 인증된 Unreal 스냅샷을 바탕으로 여섯 선반을 합성 관찰하고 상품별
  상태를 반환한다. API의 부족 기준은 정수 1~4다. 반환 출처는
  `synthetic_from_unreal_snapshot`이다.
- `POST /order-demo/api/synthetic-replenishment`, 예시 JSON
  `{"product_id":"milk","threshold":1,"approved":true}`: 직전의
  유효한 동일 세계·동일 연결 관찰을 확인하고 보충을 접수한다. 헤더
  `Idempotency-Key`가 필수다. 이미 사용한 키는 같은 접수 결과로 조회하며,
  다른 요청에 같은 키를 사용할 수 없다. `202`는 접수 또는 불명 상태이지
  집기·적재 완료를 뜻하지 않는다.
- `GET /order-demo/api/submission-lookup`에 같은 `Idempotency-Key`를
  전달하면 원래 접수를 조회한다. 조회 실패나 404만으로 미접수라고 판단할
  수 없다. 응답 유실 시 새 POST로 다시 보내지 않는다.

승인은 합성 슬롯 장부에서 출발·목적 칸을 먼저 선점한 다음 기존 웹 가상
작업에 같은 요청 ID를 넘긴다. 이후 명령·동작 결과가 불명이라면 두 선점을
유지하고 해당 세션을 차단한다. 슬롯 장부와 주행 장부는 서로 다른 DB이므로
이는 모든 장애의 원자적 복구나 물리적 정지 보장을 뜻하지 않는다.

## 재시작과 시험 범위

이 팀 선반 웹 모드의 주문·재고·요청 키는 **현재 서버 프로세스에만** 있다.
서버 재시작 후 진행 작업을 복구하지 않는다. 로컬 세계 ID 장부를 같은
경로로 유지하면 이미 사용한 Unreal 세계의 재사용을 차단한다. 장부를
삭제·교체하거나 다른 파일 또는 다른 PC를 사용하면 이 보호를 보장할 수
없다. 재시연은 기존 Unreal 게임을 종료하고 새 게임 세계로 시작한다.
기존 접수 결과를 확인하지 못한 요청은 임의로 재전송하지 않는다.

별도 격리 aMQTT와 Unreal WebSocket **대역** 종단 시험은 합성 부족 확인,
명시 승인, 픽업 이동·집기·목적지 이동·적재 및 슬롯 상태를 검증한다.
실제 Unreal 렌더링, 물리 카메라·로봇 및 공용 브로커의 검증과 구분한다.
