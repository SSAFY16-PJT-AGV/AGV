# 가상 구간 경합의 우회 후보

팀 맵 가상 웹 시연을 사용할 때 기존 시뮬레이션 API와 같은 loopback·Bearer
인증으로 `GET /simulation/tasks/{task_id}/reroute-candidate`를 조회한다.
`candidate`의 `nodes`, `edge_ids`는 관찰 당시 다른 작업의 노드·간선·공유
구역 점유 및 유휴 로봇 위치를 피하는 방향 기반 후보이며 `reservation`은
`not_reserved`, `control_effect`는 `none`이다. 다른 로봇의 경로가 바뀌면
즉시 무효가 될 수 있다. 자동 명령 발행·기존 점유 해제·예약 이전은 없다.

후보는 명시적으로 런타임에 등록된 같은 프로세스의 팀 맵 가상 실행기에서만
제공된다. 현재 인증된 수신기와 재동기화 증거·분류된 모든 활성 작업의
정지/점유·맵을 같은 SQLite 트랜잭션에서 확인한다. 정지 노드의 진입 간선은
기존 가상 경로의 직전 간선에서 계산하고, 잠긴 해당 가상 실행기의 방향
체크포인트와 대조한다. 이 방향은 `simulated_route_and_executor_checkpoint`로
표시하며 실제 로봇의 관측이나 주행 안전 증거가 아니다. 연결 세대 변경,
실행기 부재, 손상·만료·미분류·진입 방향 불명·반복 경로 및 그 밖의 증거
불충분은 `unknown`이다. 다른 작업이 이동 중이라 그 정지·점유를 모두 확인할
수 없는 경우도 보수적으로 `unknown`이다.

`no_candidate`는 해당 스냅샷의 회피 조건과 방향 규칙으로 경로를 찾지
못했다는 뜻이다. 미관측의 초기 배정 대기는 이 기능의 입력이 아니다. 후보를
실제로 사용하려면 별도의 신선한 상태 검증, 충돌 없는 원자적 예약 이전,
발행·확인 및 불명 결과 복구 계약이 필요하다. 실물이나 공유 브로커에 사용하지
않는다.
