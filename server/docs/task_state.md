# 작업 상태 기록의 범위

`server.tasks.TaskRegistry`는 설계 문서 7.1의 순서인 `PENDING → ASSIGNED → PICKING → MOVING → DELIVERING → VERIFIED → DONE`과 예외 상태 `FAILED`, `CANCELLED`를 메모리에 기록하는 독립 모듈이다.

현재 상태와 기대 상태가 일치할 때만 전이하므로, 한 프로세스 내에서 동시에 들어온 갱신 중 먼저 성공한 하나만 반영된다. 같은 작업 ID를 중복 생성하거나 정상 단계를 건너뛰는 전이는 거부한다. 작업 상태의 신뢰성은 호출자가 수행한 이벤트 검증에 달려 있다.

## 팀 협의가 필요한 임시 가정

- 예외 전이 규칙이 설계 문서에 구체화되지 않아, 이 독립 상태 모델에서는 모든 정상 미완료 상태에서 `FAILED` 또는 `CANCELLED`를 기록할 수 있다고 가정한다. 세 종료 상태(`DONE`, `FAILED`, `CANCELLED`)에서는 추가 전이가 없다.
- **이 기록은 로봇 정지, 상하차 완료, 작업 취소 완료 또는 예약 해제의 증거가 아니다.** 실제 장비와 연결하려면 각 이벤트의 진위·중복·순서와 예외 상태의 의미를 팀이 정하고 안전 처리를 별도로 구현해야 한다.
- 이 자료구조는 휘발성이며 단일 프로세스에 한정된다. 데이터베이스 저장, 서버 재시작 복구, 여러 프로세스 간 원자성, 작업 수락·중복 명령 처리와 로봇 배정은 구현하지 않았다.
- 이 모듈은 MQTT 토픽이나 메시지 필드를 추가하거나 발행하지 않는다.
