# 가상 AGV 구간 대기 관찰

기존 `SimRuntime`을 실행하는 로컬 가상 시험에서
`GET /simulation/wait-graph`를 호출한다. 다른 `/simulation` API와 같이
기존 로컬 접근 제한 및 Bearer 토큰 인증이 필요하며 응답은 `no-store`다.
이 API는 읽기 전용으로 구간을 해제하거나 이벤트를 재처리하지 않는다.

응답의 `scope`는 `isolated_simulation`, `control_effect`는 `none`이다.
`waiting`은 수신기가 현재 `SegmentOccupied`로 분류한 이벤트와 같은
SQLite 트랜잭션에서 확인된 다음 구간의 점유 소유자를 보여준다. 서로
기다리는 작업이 그래프에 있으면 `status: cycle_candidate`와
`cycle_candidates`를 반환한다. 대기가 계속될지 알 수 없으므로 이는
영구 교착 확정이나 주행·재계획 허가가 아니다. 분류된 대기는 있지만
순환이 없으면 `observed`다.

연결이 끊겼거나 재연결 중이거나, 수신기가 아직 분류하지 않은 대기
이벤트가 있거나, 이벤트·작업·현재 구간 점유·정지 증명 등의 검증에
실패하면 `unknown`이며 후보를 비운다. 너무 큰 관찰 집합도 차단한다.
관찰은 응답 작성 시점의 가상 서버 상태이며 그 직후 바뀔 수 있다.
초기 배정에서 대기하는 이유는 현재 저장되지 않아 항상
`initial_allocation_waits: not_observed`로 표시한다. `observed`와 빈
`waiting`이 전체 시스템에 대기가 없다는 뜻은 아니다.

검증은 테스트가 소유한 loopback MQTT 브로커와 2대의 가상 로봇으로
교차 구간을 경합시켜 수행한다. 일방 대기와 순환 후보, 미분류 이벤트,
손상된 이벤트, 만료된 복구 증명, 브로커 단절, 동시 조회와 단절 경합을
시험하며 조회 전후 작업·명령·이벤트·점유·복구 장부가 유지되는지
검사한다. 실제 하드웨어의 위치, 후단 이탈, 정지나 물리적 안전을
확인한 시험이 아니다. 사용자 개입 없는 자동 해제나 재계획은 제공하지
않는다.
