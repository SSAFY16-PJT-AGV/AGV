# 차단된 팀 선반 기록의 읽기 전용 조사

우회 이후 서버가 복구를 차단해도, 보존한 팀 선반 상태 폴더에서 주문 ID와
품목, 당시 장부 상태 및 기록된 슬롯 선점을 로컬에서 조사할 수 있다.
**가상 시연을 완전히 중지한 뒤** 저장소 루트에서 실행한다.

```powershell
.\.venv\Scripts\python.exe -m server.tools.inspect_team_shelf_recovery `
  --state-dir 'D:\관통\team-shelf-state'
```

명령은 파일을 쓰거나 복구하지 않고, 원본 SQLite를 메모리로 복사해 확인한다.
브로커·Unreal·실물 장치에 연결하지 않으며 주문이나 명령을 발행하지 않는다.
`-wal`, `-shm`, `-journal` 파일이 있거나 파일이 읽는 중 바뀌거나 손상된
경우에는 사용 가능한 결과를 추정하지 않고 실패한다. 실패했다고 원본이나
저널 파일을 지우지 않는다. 도구를 재실행하기 전 상태를 보존하고 원인을
조사한다.

출력의 모든 주문 `status`와 24칸 `state`는 **unknown**이다. 주문의
`recorded_state`는 저장됐던 과거 값일 뿐 현재 완료 여부가 아니다. 슬롯의
`claim_recorded: true`는 선점 기록이 있다는 뜻이고 `null`은 안전하거나 빈
칸이라는 뜻이 아니다. DB 바인딩이 일치하지 않거나 확인할 수 없으면 각각
`binding: mismatch` 또는 `unavailable`이 표시된다. 파일 사이의 상태는 단일
스냅샷이 아니므로 `matched`도 실제 완료나 재고의 검증을 의미하지 않는다.

요청 키, 인증값, 로봇 세션, 원본 이벤트·액션, DB 경로는 출력하지 않는다.
최근 주문은 최대 500건이며 `orders_truncated`가 true면 일부만 표시한 것이다.
이 도구에는 원본 변경·주행 재개·점유 해제 기능이 없다. 저장 기록과 동일
Unreal 월드/로봇 상태의 재검증은 별도 작업이다.
